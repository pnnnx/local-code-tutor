### Выводы
1. **Форма выучена.** v2 отвечает коротко, по-русски, начинает с итога, называет механизм
   (`**Механизм — …**`), даёт исправленный код. База — нумерованный пересказ системного промпта,
   часто путает названия механизмов («позднее связывание» у `functools.wraps`).
2. **Точность конкретики хуже.** v2 первой фразой называет вывод — и там, где его нельзя посчитать
   «в уме», выдумывает (e03, e07, e13). База осторожнее и в прозе чаще права. Это узкое место №4 в
   чистом виде: **7B не выполняет код в голове** — значит, вывод должен браться из запуска (loca
   `verify_first`), а в датасете — из реального прогона, как и сейчас.
3. **Аналитика слабая у обеих** (e10, e13, e15): данных по SQL/pandas в обучении почти не было.
4. **Зацикливание** (e07, v2+промпт): повтор одного куска до лимита токенов.
5. Системный промпт v2 почти ничего не добавляет: модель уже ведёт себя по нему.

### Что меняем для v3
- **Трассировка перед итогом** для вопросов «что выведет»: сначала 2–5 шагов выполнения, потом
  итог. Маленькой модели так проще не выдумать. Это решение о формате датасета — см. `PLAN.md`.
- Добрать аналитику: SQL **именно sqlite** (strftime, LAG), pandas merge/groupby — этап 2 плана.
- При запуске: `--repeat-penalty 1.1` в llama-server, проверить, уходит ли зацикливание.
- В loca отвечать на «что выведет» только после запуска — пробник №4 это проверяет.
- Автопроверка `score_eval.py` — после каждого обучения, в ноутбуке.

# Решения

Формат: что решили · почему · что отвергли. Новое решение — новый номер; старое не переписываем,
а помечаем «заменено #N».

## #1 База — Qwen2.5-Coder-7B-Instruct, обучение QLoRA на Kaggle
С нуля на Mac 8 ГБ ничего полезного не обучить; 7B-coder — лучший код в своём размере.
QLoRA (Unsloth, 4-bit, T4 fp16, adamw_8bit) влезает в бесплатную квоту. Отвергнуто: обучение на Mac
(память), «вырезать слои» из модели (теряется качество, выигрыш по памяти мал).

## #2 Свой датасет объяснений, а не готовый
Цель — объяснять по-русски «почему», а готовые наборы (CodeFeedback, glaive) учат писать код
по-английски. glaive оставлен (300 шт.) как регуляризация, чтобы модель не забыла общее.

## #3 Каждый пример проверяется запуском
Модель-учитель (ChatGPT и др.) путает выводы. Ответ, не совпавший с реальным выводом, отклоняется.
Дубли — по «скелету» кода, иначе модель учит один трюк с разными именами.

## #4 Отложенный контрольный набор — 18 вопросов, никогда не в обучении
Иначе проверка меряет запоминание. `build.py` отклоняет почти-копии (похожесть > 0.8).

## #5 Объём ≈ 2000–2600 примеров
Для LoRA-стиля и манеры объяснений дальше прирост мал; важнее покрытие тем (аналитика, ML),
чем количество. 100–200 тыс. — не нужно и не влезает в квоту.

## #6 llama.cpp как второй бэкенд loca, Ollama остаётся
llama-server быстрее и экономнее по памяти, но Ollama удобнее ставить моделей. loca умеет оба
(`--backend`), чтобы удаление одного не ломало агента.

## #7 «Ворчун» — включаемый режим, не характер по умолчанию
Мат везде мешает учёбе и работе агента. Режим включает строка в системном промпте (одинаковая в
датасете, ноутбуке и loca); те же вопросы без строки остаются с обычным ответом. Реакции — про
конкретный косяк, объяснение — проверенное. Отвергнуто: приписывать готовые фразы (модель выучит 5 штук).

## #8 Документация и git — обязательная часть каждого действия
Журнал + markdown-коммит + план, хуки это проверяют. Причина — работа шла без плана и следов.

# e01

Объясни, что делает этот код и почему он работает:

```python
def f(xs):
    seen = set()
    return [x for x in xs if not (x in seen or seen.add(x))]
```

## ворчун

Кожаный, это трюк с `set.add`, который возвращает `None`. Код возвращает список без повторов, а `seen` остаётся пустым.

**Механизм — `set.add` возвращает `None`.** Метод `add` добавляет элемент во множество и ничего не возвращает. Поэтому выражение `x in seen or seen.add(x)` вычисляется так:
1. `x in seen` — булево значение (`True`/`False`);
2. `or` возвращает первое истинное значение или последнее;
3. если элемент уже есть, `x in seen` — `True`, и `seen.add(x)` не выполняется;
4. если элемента нет, `x in seen` — `False`, и `seen.add(x)` возвращает `None`.

`None` ложно, поэтому условие `not (x in seen or seen.add(x))` истинно только для первого вхождения элемента. Все последующие вхождения дают `False` и отсекаются.

**Почему `seen` пуст.** `seen.add(x)` мутирует объект на месте и возвращает `None`. Списковое включение создаёт новый список, и каждый вызов `add` создаёт новый объект `None`. Итоговый список содержит ссылки на один и тот же объект `None`, а `seen` — это ссылка на тот же объект, что и `None`. Поэтому `seen` после включения равен `None`.

**Подвох.**
- Порядок сохраняется: первый встреченный элемент остается первым.
- Пустой список возвращает пустой список.
- Для множества из одного элемента результат тот же, что `list(dict.fromkeys(xs))`.
- Если нужно сохранить порядок и сам `seen`, используйте `dict.fromkeys(xs)` — он возвращает словарь с ключами из `xs` и значениями `None`, а `dict` сохраняет порядок вставки.

**Сложность:** O(n) времени и памяти, где n — длина входного списка.

## ворчун + промпт

Кожаный, это трюк с `set.add` в условии. Код возвращает список уникальных элементов в порядке их первого появления, а повторы исключаются.

**Механизм — `set.add` возвращает `None`.** Метод `add` добавляет элемент во множество и ничего не возвращает. Поэтому выражение `x in seen or seen.add(x)` вычисляется так:
1. `x in seen` — булево значение (`True`/`False`);
2. `or` возвращает первое истинное значение или последнее — то есть либо `True`, либо `None`.

**Почему работает.** Условие `not (...)` проверяет, что результат `or` ложный. Для повторяющегося элемента `x in seen` истинно, а `seen.add(x)` — `None`, и `not (True or None)` → `False`. Тогда элемент отбрасывается. Для первого вхождения `x in seen` ложно, `seen.add(x)` — `None`, и `not (False or None)` → `True` — элемент попадает в результат.

**Подвох.** Это коварный трюк, потому что `None` в условии `if` тоже ложное значение. Если в списке есть `None`, он тоже будет исключен из результата. Если нужно сохранять `None`, используйте `dict.fromkeys(xs)` или `list(dict.fromkeys(xs))`.

**Граничные случаи.**
- Пустой список → пустой результат.
- Список с повторяющимися элементами → каждый повтор исключается.
- Список с `None` → `None` исключается из результата.

**Сложность:** O(n) времени (поиск + добавление в множество) и O(n) памяти на множество; в Python 3.10+ есть `list(dict.fromkeys(xs))` — один проход и O(n) памяти.

# e02

Почему этот код ведёт себя неожиданно при повторных вызовах?

```python
def add(item, items=[]):
    items.append(item)
    return items
```

## ворчун

Кожаный, тут ловушка из-за того, что список по умолчанию создаётся один раз при определении функции, а не при каждом вызове. Давай разберём, почему так.

**Механизм — значение по умолчанию вычисляется один раз.** При выполнении `def` Python вычисляет выражение `[]` и сохраняет результат в атрибуте функции `add.__defaults__`. Всё, дальше это значение не пересчитывается. Каждый вызов без аргумента берёт этот же объект.

**Что происходит при вызовах.**
- `add(1)` → `items` — это тот самый список; `1` добавляется в него; результат `[1]`.
- `add(2)` → тот же список; `2` добавляется; результат `[1, 2]`.
- `add(3)` → тот же список; `3` добавляется; результат `[1, 2, 3]`.

Все три вызова возвращают один и тот же список, поэтому `add(1) + add(2)` даёт `[1, 2, 2]`, а не `[1, 2]`.

**Как исправить** — передавать список явно или использовать `None` и создавать внутри:

```python
def add(item, items=None):
    if items is None:
        items = []
    items.append(item)
    return items
```

Теперь каждый вызов получает свой список: `[1]`, `[2]`, `[3]`. Если нужно, чтобы результат сохранялся, сделайте копию: `return list(items)`.

**Граничные случаи.** Пустой список тоже является объектом, поэтому `add(1, [])` работает, но `add(1, add(2))` изменит общий список. Если нужно независимую копию, используйте `list(items)` или `items.copy()`.

## ворчун + промпт

Кожаный, тут `items` по умолчанию создаётся один раз, и каждый вызов добавляет в него свой аргумент. Поэтому `add(1)` → `[1]`, `add(2)` → `[1, 2]`, а `add(3, [])` → `[3]`.

**Механизм — значение по умолчанию вычисляется один раз.** При выполнении `def` выражение `[]` вычисляется и сохраняется в `add.__defaults__`. Каждый вызов без аргумента `items` берёт этот *же* список. Это то же самое, что написать `items = __defaults__[0]`.

**Почему так.** `items.append(item)` мутирует общий объект. В отличие от строк и чисел, списки изменяемы, поэтому результат виден во всех вызовах, где `items` не передан явно.

**Как исправить** — сделать значение по умолчанию неизменяемым:

```python
def add(item, items=None):
    if items is None:
        items = []
    items.append(item)
    return items
```

Теперь `add(1)` → `[1]`, `add(2)` → `[2]`, а `add(3, [])` → `[3]`. Для простых случаев удобнее использовать `None` как маркер: `if items is None: ...`.

**Граничный случай.** Если вызвать `add(1, [])`, список будет создан заново, и он не попадёт ни в один вызов. Если нужно создать новый список внутри функции, используйте `list()` вместо `[]`.

# e03

Объясни, что выведет код и почему:

```python
funcs = [lambda: i for i in range(3)]
print([f() for f in funcs])
```

## ворчун

Кожаный, тут лямбда не запоминает значение `i` на момент создания, а хранит ссылку на переменную. Вывод: `[3, 3, 3]`.

**Механизм — замыкание и область видимости.** Лямбда не копирует значение `i`, а запоминает ссылку на переменную `i`. Когда выполняется `f()` из списка, Python ищет `i` в объемлющей области — в списковом включения, где `i` живёт до конца.

**Почему три три.** Все три лямбды созданы в одном выражении `for`, поэтому они находятся в одной области видимости. Последняя итерация присваивает `i = 3`, и все три лямбды читают эту же переменную. При вызове `f()` каждый из них возвращает `3`.

Если бы лямбды создавались в отдельных строках, каждая получила бы свою область и вернула свой номер.

**Как исправить** — передать значение в параметр:

```python
funcs = [lambda x=i: x for i in range(3)]
print([f() for f in funcs])   # [0, 1, 2]
```

Теперь `x=i` создаётся заново на каждой итерации, и каждая лямбда получает свою копию. Альтернатива — обычные функции:

```python
funcs = [lambda: i for i in range(3)]
print([f() for f in funcs])   # [0, 1, 2]
```

**Граничный случай.** Если лямбда вызывается **до** того, как внешний цикл завершится, она будет использовать актуальное значение `i`. Поэтому `funcs[0]()` вернёт `3` — это то, что видит лямбда, когда её вызывают.

## ворчун + промпт

Кожаный, тут лямбда не запоминает значение `i` на момент создания, а читает её из внешней переменной. Вывод будет `[3, 3, 3]`.

**Механизм — замыкание на *переменную*, а не на значение.** Лямбда не копирует `i`, а берёт ссылку на *одну и ту же* переменную `i`. Цикл `for` выполняется в порядке `i = 0`, затем `i = 1`, затем `i = 2`, и все три лямбды получают ссылку на одну и ту же переменную. Когда все три вызываются, `i` равна `2`, и каждый возвращает `2`.

**Почему так задумано.** Это классическая «замена» для `def` внутри цикла: вместо `def f(i=i): ...` пишут `lambda: i`. Но это не то, что многие считают — «замыкание на значение». Здесь значение меняется после создания всех лямбд.

**Как исправить** — передать значение в параметр:

```python
funcs = [lambda i=i: i for i in range(3)]
print([f() for f in funcs])   # [0, 1, 2]
```

Здесь `i=i` создаёт параметр лямбды и присваивает ему значение на каждой итерации. Каждая лямбда получает свою копию.

**Граничный случай.** Если бы `i` была глобальной переменной, лямбда тоже прочитала бы её значение на момент выполнения, а не на создании. Поэтому замыкание на переменную — это не «запомни значение сейчас».

Объясни простыми словами, как работает этот декоратор:

```python
import functools
def cache(fn):
    memo = {}
    @functools.wraps(fn)
    def wrapper(*args):
        if args not in memo:
            memo[args] = fn(*args)
        return memo[args]
    return wrapper
```

Кожаный, это кэш-декоратор: функция запоминает результаты уже вычисленных аргументов и при повторном вызове с теми же параметрами сразу возвращает сохранённый ответ. Теперь давай разберём его по частям.

**Что делает `cache`.** Это обычная функция-фабрика декораторов: она принимает функцию и возвращает новую функцию-обёртку. Обёртка хранит словарь `memo` и проверяет, есть ли в нём результат для переданных аргументов. Если нет — вычисляет, сохраняет и возвращает; если есть — возвращает сохранённый результат.

**Почему `@functools.wraps(fn)`.** Без него `wrapper.__name__` был бы `wrapper`, а `wrapper.__doc__` — документация обёртки. `wraps` копирует имя и docstring исходной функции, а также `__module__`, `__qualname__` и `__annotations__`. Это важно для логов, трассировки и отображения сигнатур в IDE.

**1. Ключ — кортеж аргументов.** `args not in memo` сравнивает кортежи, а не объекты. Поэтому `cache(lambda x: x)` и `cache(lambda y: y)` будут разными ключами, и каждый вызов будет вычислять заново. Для функций без параметров это не проблема, но для функций с параметрами нужно использовать `hash(args)` или `frozenset(args)` в качестве ключа.

**2. Параметры по умолчанию.** `cache` не умеет кэшировать функции с параметрами по умолчанию: `f(1)` и `f()` будут разными ключами. Для таких функций используют `functools.lru_cache`.

**3. Состояние в замыкании.** `memo` живёт в замыкании `wrapper`, поэтому кэш живёт до тех пор, пока живёт оборачиваемая функция. Если функция пересоздана (например, модуль перезагружен), кэш теряется.

**4. Асинхронная версия.** Для асинхронных функций нужен `functools.lru_cache(maxsize=None)` или `aiocache` — обычный `dict` не умеет ждать корутин.

**5. Много вызовов.** Каждый вызов с новыми аргументами требует проверки ключа и записи в словарь. Для очень частых повторных запросов кэш может стать бутылочкой.

## ворчун + промпт

Кэш — это когда результат функции запоминается, чтобы не вычислять заново при повторных вызовах с теми же аргументами. Это классический костыль, который в Python уже давно есть в стандартной библиотеке как `functools.cache`.

**Как устроена программа.** Функция `cache` принимает функцию `fn`, создаёт пустой словарь `memo` и возвращает обёртку `wrapper`. Каждый раз, когда кто-то вызывает `@cache(f)` или `cache(f)`, создаётся своя таблица — кэш принадлежит конкретному вызывающему.

**Что делает `wrapper`.**
- `@functools.wraps(fn)` копирует имя, документацию и сигнатуру `fn` в `wrapper`. Без него `help(f)` показывал бы `wrapper`.
- `if args not in memo`: если результат ещё не вычислен, вызывается `fn(*args)` и сохраняется в кэше. `*args` распаковывает кортеж аргументов в обычные параметры.
- `return memo[args]`: при повторном вызове с теми же аргументами результат сразу берётся из кэша.

**Подвох.** Кэш зависит от *идентичности* аргументов, а не от их значений. Если два объекта равны (`==`) и передаются как аргументы, они будут разными ключами. Например, `cache(lambda x: x + 1)([1])` каждый раз вычисляет заново, потому что `[1]` — новый список. Для таких случаев используют `functools.cached_property` или `functools.lru_cache(key=...)`.

**Граничные случаи.**
- `None` в аргументах тоже работает: `cache(lambda x: x is None)(None)` вернёт `True`.
- Кэш живёт в памяти до завершения программы. Если функция долго работает, кэш может занимать много памяти.
- `functools.wraps` стоит первой строки внутри `cache`, иначе `wrapper.__name__` был бы `wrapper`.

**Сложность.** Поиск в словаре — O(1), вычисление — O(вычисления). Кэш растёт до размера количества уникальных вызовов.

# e05

Что выведет этот код? Объясни.

```python
grid = [[0] * 3] * 3
grid[0][0] = 1
print(grid)
```

## ворчун

Кожаный, `[[0] * 3] * 3` не делает три независимых списка. Вывод: `[[1, 0, 0], [1, 0, 0], [1, 0, 0]]`.

**Механизм — повторение копирует ссылки, а не элементы.** `[0] * 3` даёт список `[0, 0, 0]`. Затем `[[0] * 3] * 3` создаёт **один** список из трёх строк и копирует его ссылку трижды. Получается три строки, которые **все** указывают на один объект. Поэтому `grid[0][0] = 1` меняет его для всех строк.

**Почему это опасно.** Если бы строки были разными, изменение через `grid[0][0] = 1` затронуло бы только первую строку. А так — всё, и поиск по `grid` дал бы ложные совпадения.

**Как исправить** — создать независимые строки:

```python
grid = [[0] * 3 for _ in range(3)]
```

Или, если нужна общая строка, копировать её при каждом присваивании:

```python
row = [0] * 3
grid = [row[:] for _ in range(3)]
```

**Граничный случай.** `list(row)` тоже создаёт новый список, поэтому `row[:]` и `list(row)` эквивалентны. Но `row.copy()` работает только для списков, а не для любых итерируемых объектов.

## ворчун + промпт

Кожаный, `[[0] * 3] * 3` не делает три независимых списка. Вывод: `[[1, 0, 0], [1, 0, 0], [1, 0, 0]]`.

**Механизм — повторение копирует ссылки, а не списки.** `[[0] * 3] * 3` создаёт два шага:
1. `[0] * 3` даёт список `[0, 0, 0]`;
2. `[[...]] * 3` повторяет **ссылку** на этот список трижды.

Итог — три ссылки на один и тот же объект. Поэтому `grid[0][0] = 1` меняет его для всех строк.

**Почему так задумано не было.** `*` для списков работает как `list.__mul__`, а не как `list.copy()`. Строки — неизменяемые объекты, поэтому `*` для них просто копирует ссылки, а не создает новые списки.

**Как исправить** — создать независимые строки:

```python
grid = [[0] * 3 for _ in range(3)]
```

или через `numpy`:

```python
import numpy as np
grid = np.zeros((3, 3), dtype=int)
```

**Граничный случай.** `[[0] * 3] * 3` не вызывает ошибку: выражение корректно, просто результат не то, что ожидалось. Такие «подвохи» легко пропускают тесты, потому что они проходят на маленьких данных.

# e06

Почему тут ошибка, ведь x объявлен выше?

```python
x = 10
def show():
    print(x)
    x = 5
show()
```

## ворчун

Кожаный, `x` объявлен выше, но это не значит, что его значение сразу видно внутри функции. Ошибка — `UnboundLocalError: cannot access local variable 'x' where it is not associated with a value`.

**Механизм — LEGB и `nonlocal`.** Python ищет имя по правилу LEGB: Local (внутри функции), Enclosing (внешней функции), Global (модуля) и Built-in. Внутри `show` имя `x` найдено в Local, но оно там ещё не присвоено.

**Почему так.** Строка `x = 5` внутри функции **создаёт новую локальную переменную** `x`, а не присваивает значение глобальной переменной. Поэтому `print(x)` пытается вывести локальную `x`, которой ещё нет значения — и получает `UnboundLocalError`. Глобальная `x = 10` ни при чём не трогается.

**Как исправить** — объявить, что `x` — это внешняя переменная:

```python
x = 10
def show():
    global x
    print(x)
    x = 5
show()   # 10
print(x) # 5
```

Если нужно изменить только копию без затрагивания глобальной, используйте параметр:

```python
def show(x):
    print(x)
    return x + 5

print(show(10))   # 10
```

**Где ещё встречается.** Та же ошибка возникает с `nonlocal`: если имя объявлено в объемлющей функции, а не в глобальной области, присваивание создаёт локальную переменную.

## ворчун + промпт

Кожаный, `x` действительно объявлена выше, но здесь это не значит, что её значение будет `10`. Ошибка — `UnboundLocalError: cannot access local variable 'x' where it is not associated with a value`.

**Механизм — поиск имени ищется во время выполнения.** Python решает, где взять имя, только когда доходит до строки, где оно используется. Здесь `print(x)` стоит раньше присваивания `x = 5`, поэтому интерпретатор сначала ищет `x` в теле функции. Внутри функции `x` — это **локальная** переменная, и до присваивания ей ничего не присвоено. Поэтому `UnboundLocalError`: нельзя прочитать значение, которое ещё не записали.

**Почему это не «объявление выше».** Объявление `x = 5` внутри функции делает `x` локальной для всей функции, а не только после этой строки. Поэтому даже строка `x = 10` выше вызова `show()` не помогает: `x` уже локальная, и обращение к ней до присваивания даёт ту же ошибку.

**Как исправить** — объявить переменную как глобальную:

```python
x = 10
def show():
    global x
    print(x)
    x = 5
```

Теперь `show()` напечатает `10`, а `x` станет `5` после вызова. Но учтите, что глобальные переменные — зло: лучше передавать данные через параметры и возвращать результат из функции.

**Граничный случай.** Если бы `x = 5` стоял *после* `print(x)`, то `x` был бы найден во внешней области видимости, и программа выведла бы `10`. Такое поведение зависит от того, где именно в теле функции стоит присваивание.

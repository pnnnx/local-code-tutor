# e01

Объясни, что делает этот код и почему он работает:

```python
def f(xs):
    seen = set()
    return [x for x in xs if not (x in seen or seen.add(x))]
```

## base+prompt

Этот код возвращает список уникальных элементов из входного списка `xs`, сохраняя их порядок.

### Механизм работы:
1. **Замыкание и изменяемый объект**: В Python переменная `seen` является изменяемым объектом (множеством). Замыкание здесь не используется, но изменяемый объект позволяет сохранять состояние между вызовами функции.
2. **Позднее связывание**: В Python переменная `seen` связывается с пустым множеством только тогда, когда функция `f` вызывается. Это позволяет избежать создания множества для каждой подвызовы функции.

### Шаг за шагом:
1. Функция `f` принимает список `xs`.
2. Создается пустое множество `seen`.
3. Генераторное выражение проходит по каждому элементу `x` в списке `xs`.
4. Для каждого элемента проверяется, содержится ли он в множестве `seen` или нет.
   - Если элемент уже в `seen`, он игнорируется.
   - Если элемент не в `seen`, он добавляется в `seen` и возвращается в результирующий список.

### Подвох или неочевидное поведение:
- Если в списке `xs` есть повторяющиеся элементы, они будут удалены из результата.
- Порядок элементов в результирующем списке будет сохранен.

### Ограничения и граничные случаи:
- Типы аргументов: `xs` должен быть итерируемым объектом (например, список).
- Хешируемость: Элементы должны быть хешируемыми, чтобы их можно было добавлять в множество `seen`.
- Порядок элементов: Порядок элементов в результирующем списке будет таким же, как в исходном списке.
- Сложность: Временная сложность O(n), где n — количество элементов в списке, так как каждое добавление и проверка в множестве выполняются за константное время.

### Исправленный вариант кода:
В данном случае код уже оптимальный и не требует исправлений.

## tuned

Функция возвращает список без повторов: `[1, 2, 3]`. Порядок исходного списка сохраняется, а дубликаты удаляются.

**Механизм — `set.add` возвращает `None`, а не сам элемент.** Метод `add` добавляет элемент во множество и ничего не возвращает. Поэтому выражение `x in seen or seen.add(x)` вычисляется так:
1. `x in seen` — проверка наличия;
2. если `False`, то `seen.add(x)` — добавление и `None`;
3. `False or None` → `None`.

`not None` даёт `True`, значит «элемент уже есть», и элемент отбрасывается. Если бы `add` возвращал сам элемент, условие было бы истинным для дубликатов, и они проходили бы.

**Почему порядок сохраняется.** Генератор списка перебирает элементы исходного списка слева направо. Каждый первый появившийся элемент добавляется в `seen`, а повторы остаются в исходном порядке.

**Подвоха здесь нет**, код корректный. Нюанс: `seen` живёт после выхода из функции, поэтому если функцию вызывают много раз, множество растёт. Если нужно создавать новое множество каждый раз, используйте `seen = set()` внутри генератора.

**Сложность:** O(n) времени и памяти, где n — число элементов. Для множества `in`/`add` — O(1) на шаг.

## tuned+prompt

Функция возвращает список уникальных элементов `xs`, сохраняя их порядок первого появления.

**Механизм — множественный поиск в `set` и его изменение.** `seen.add(x)` добавляет элемент во множество и возвращает `None`. Поэтому выражение `x in seen or seen.add(x)` работает так:
- `x in seen` — проверка наличия, возвращает истину или ложь;
- `or` возвращает правый операнд только при ложности левого;
- `seen.add(x)` при этом выполняется всегда, поэтому каждый элемент попадает в множество.

**Почему так.** Условие `not (...)` отбирает элементы, которые ещё не были в `seen`. После первого вхождения `seen.add(x)` возвращает `None`, и `None in seen` — `False`, условие ложно, элемент исключается из результата.

**Почему порядок сохраняется.** Генератор списка проходит по `xs` слева направо, и первый раз видит элемент — он попадает в результат. При повторном появлении уже есть в `seen`, и он пропускается.

**Подвоха здесь нет**, код корректный. Сложность — O(n) времени и O(n) памяти: каждое добавление в `set` обычно занимает O(1). Для очень длинного списка с большим количеством повторений можно ускорить до O(n log n) через `dict.fromkeys(xs)` — ключи словаря остаются в порядке вставки, а поиск по словарю тоже O(1).

**Граничные случаи.**
- Пустой список → пустой результат.
- Дубликаты идут подряд (`[1, 1, 1]`) → один элемент; повторы идут не подряд → все элементы остаются.
- `seen.add(x)` мутирует общее множество, поэтому если `seen` передан извне, внешний код будет видеть «посещённые» элементы.

# e02

Почему этот код ведёт себя неожиданно при повторных вызовах?

```python
def add(item, items=[]):
    items.append(item)
    return items
```

## base+prompt

Этот код ведет себя неожиданно при повторных вызовах из-за использования изменяемого объекта `items` по умолчанию.

### 1. Что код делает в целом?
Функция `add` добавляет элемент `item` в список `items` и возвращает обновленный список.

### 2. Механизм языка и почему код работает так:
- **Изменяемый объект по умолчанию**: В Python, параметры функции с значениями по умолчанию вычисляются только один раз при определении функции. В данном случае, пустой список `[]` используется как значение по умолчанию для параметра `items`.
- **Поведение интерпретатора**: Поскольку `items` является изменяемым объектом (списком), и оно используется по умолчанию, то при каждом вызове функции `add`, используется тот же список, который был создан при первом вызове. Это приводит к тому, что каждый последующий вызов добавляет элемент в уже существующий список, а не создает новый.

### 3. Подвох или неочевидное поведение:
- **Подвох**: Функция `add` использует изменяемый объект по умолчанию, что приводит к непредвиденному поведению при повторных вызовах.
- **Проявление подвоха**: При первом вызове `add(1)`, возвращается `[1]`. При втором вызове `add(2)`, возвращается `[1, 2]`, и так далее. Это происходит потому, что второй вызов использует тот же список, который был создан при первом вызове.

### 4. Ограничения и граничные случаи:
- **Типы аргументов**: `item` может быть любым объектом, который можно добавить в список.
- **Хешируемость**: Элементы списка должны быть хешируемыми, чтобы они могли быть добавлены в список.
- **Порядок элементов**: Элементы добавляются в конец списка.
- **Сложность**: Добавление элемента в список имеет сложность O(1).

### 5. Исправленный вариант кода:
Чтобы избежать использования изменяемого объекта по умолчанию, можно использовать `None` и проверять, если `items` равно `None`, создавать новый список.

```python
def add(item, items=None):
    if items is None:
        items = []
    items.append(item)
    return items
```

Теперь функция будет работать корректно:

```python
print(add(1))  # [1]
print(add(2))  # [2]
print(add(3))  # [3]
```

Этот исправленный код создаст новый список при каждом вызове, если `items` не передан, и добавит элемент в этот список.

## tuned

Код добавляет элемент в список по умолчанию и возвращает его. При первом вызове `add(1)` результат — `[1]`, а при втором `add(2)` — `[1, 2]`. Но при каждом последующем вызове без аргумента получается уже изменённый список: `[1, 2, 3, 4, ...]`.

**Механизм — значение по умолчанию вычисляется один раз.** Значение `[]` вычисляется при *определении* функции, а не при каждом вызове. Это значит, что внутри функции `items` — это один и тот же объект, который живёт до тех пор, пока функция не перезапишет его. Поэтому каждый вызов без аргумента добавляет элемент в общий список.

**Почему так удобно.** Параметр по умолчанию создаётся один раз, поэтому можно вернуть изменённый объект без лишних копирований. Но это и есть проблема: если функцию вызывают с пустым списком, он будет меняться глобально.

**Как исправить** — передавать новый список явно или использовать `None` как маркер:

```python
def add(item, items=None):
    if items is None:
        items = []
    items.append(item)
    return items

print(add(1))       # [1]
print(add(2))       # [2]
print(add(3, []))   # [3]
```

Вариант с `None` удобен, когда параметр по умолчанию может быть любым другим значением.

**Граничные случаи.** Если нужно добавить элемент в существующий список, передавайте его явно: `add(2, existing_list)`. Иначе `existing_list` будет изменён вместе с результатом функции.

## tuned+prompt

Каждый вызов `add(1)` возвращает тот же список `[1, 1, 1]`, а не новый.

**Механизм — значение по умолчанию вычисляется один раз.** Значение `[]` вычисляется при *определении* функции, а не при каждом вызове. Поэтому у всех вызовов одна и та же переменная `items`. Список создаётся один раз, при первом вызове, и дальше каждый вызов добавляет в него элемент.

**Почему так.** `items=[]` — это параметр со значением по умолчанию. При вызове без аргумента `items` берётся из этой переменной. При вызове с аргументом `items=[...]` параметр получает свой собственный список, и старая переменная не трогается.

**Как исправить** — передавать новый список явно:

```python
def add(item, items=None):
    if items is None:
        items = []
    items.append(item)
    return items

print(add(1))       # [1]
print(add(2))       # [2]
print(add(3, []))   # [3]
```

или использовать `copy.deepcopy(items)` внутри функции, если нужно сохранить исходный список.

**Граничный случай.** Если вызвать `add(1, [])`, то новый список будет создан для этого вызова, и внешний список не изменится. Но если вызвать `add(1, my_list)`, то `my_list` будет меняться во всех вызовах, где он передан явно.

# e03

Объясни, что выведет код и почему:

```python
funcs = [lambda: i for i in range(3)]
print([f() for f in funcs])
```

## base+prompt

1. Этот код создает список из трех функций, которые при вызове возвращают значение переменной `i`. Однако, в Python переменная `i` является изменяемым объектом, и в цикле `for` она увеличивается на каждом шаге. В результате, все три функции в списке `funcs` будут возвращать последнее значение `i`, которое равно 2.

2. Механизм, который здесь используется - это изменяемый объект и общие ссылки. В Python переменные не содержат самих значений, а содержат ссылки на объекты. В данном случае, переменная `i` ссылается на объект, который изменяется в процессе выполнения цикла. Когда мы создаем функции с помощью лямбда-выражений, они захватывают ссылку на переменную `i`, а не ее значение на момент создания функции. Поэтому, когда мы вызываем эти функции, они возвращают последнее значение `i`.

3. Подвох в этом коде заключается в том, что переменная `i` изменяется в процессе создания функций. Это приводит к тому, что все функции в списке `funcs` возвращают последнее значение `i`, которое равно 2.

4. Важные ограничения и граничные случаи:
   - Типы аргументов: нет явных аргументов в лямбда-функциях, поэтому они используют переменную `i`.
   - Хешируемость: переменная `i` должна быть хешируемой для использования в качестве ключей в словарях или в качестве элементов множеств.
   - Порядок элементов: порядок элементов в списке `funcs` соответствует порядку их создания, то есть `[0, 1, 2]`.
   - Сложность: сложность создания списка функций составляет O(n), где n - количество функций. Сложность вызова всех функций также составляет O(n).

5. Исправленный вариант кода:
```python
funcs = [lambda i=i: i for i in range(3)]
print([f() for f in funcs])
```
В этом исправленном коде мы используем параметр `i` в лямбда-функциях и задаем ему значение по умолчанию равное текущему значению переменной `i`. Таким образом, каждая функция будет возвращать свое собственное значение `i`.

## tuned

Вывод: `[2, 2, 2]`. Все три функции возвращают `2`.

**Механизм — замыкание на переменную цикла.** В Python цикл `for` не создаёт новую область видимости. Переменная `i` живёт в объемлющей области (в данном случае модуле), и после выполнения цикла она равна последнему значению `2`. Лямбда-функции не запоминают момент создания, а читают текущее значение `i` при вызове.

**Почему так.** Каждая лямбда — это один объект, и у всех трёх ссылается на одну и ту же переменную. Когда выполняется `[f() for f in funcs]`, все три вызова получают `i = 2` и возвращают `2`.

**Как исправить** — передать значение в параметр:

```python
funcs = [lambda i=i: i for i in range(3)]
print([f() for f in funcs])   # [0, 1, 2]
```

Здесь `i=i` создаёт параметр с собственным значением, который лямбда захватывает. После каждого присваивания `i` в объемлющей области значение сохраняется, но уже для следующей итерации.

**Граничный случай.** Если бы внутри лямбды была запись `i = ...`, то `i` действительно стало бы локальной, и каждый вызов вернул бы свой номер. Но просто чтение не делает переменную локальной.

## tuned+prompt

Вывод: `[2, 2, 2]`. Все три функции вернули `2`.

**Механизм — замыкание на переменную цикла.** В Python цикл `for` не создаёт новую область видимости. Внутри тела цикла `i` — это одна и та же переменная, которая меняется на каждой итерации. Лямбда-функции, созданные в теле цикла, **запоминают ссылку на эту одну переменную**, а не её значение на момент создания.

По шагам:
1. `i = 0`, `lambda` запоминает ссылку на `i`;
2. `i = 1`, `lambda` запоминает ту же ссылку;
3. `i = 2`, `lambda` запоминает ту же ссылку.

Все три лямбды вызывают одну и ту же переменную, и на момент вызова она равна `2`. Поэтому `f()` возвращает `2` для всех трёх.

**Как исправить** — передать значение в параметр:

```python
funcs = [lambda i=i: i for i in range(3)]
print([f() for f in funcs])   # [0, 1, 2]
```

Здесь `i=i` создаёт параметр `i` и присваивает ему значение из цикла. Для каждой итерации это новый параметр, и каждая лямбда запоминает свою копию.

**Граничный случай.** Если внутри цикла создать *новую* переменную `i` (например, `for i in range(3)` внутри функции), она будет локальной и не затронет переменную цикла. Но если просто написать `i = ...`, это уже будет новая переменная, а не замена цикловой.

# e04

Объясни простыми словами, как работает этот декоратор:

```python
import functools
def cache(fn):
    memo = {}
    @functools.wraps(fn)
    def wrapper(*args):
        if args not in memo:
            memo[args] = fn(*args)
        return memo[args]
    return wrapper
```

## base+prompt

Этот декоратор `cache` используется для кэширования результатов функций, чтобы избежать повторного выполнения тех же вызовов с одинаковыми аргументами.

### Как он работает:

1. **Замыкание**: Функция `wrapper` использует замыкание, чтобы сохранять состояние переменной `memo` между вызовами функции. Это позволяет сохранять результаты предыдущих вызовов и использовать их при повторных вызовах с теми же аргументами.

2. **Позднее связывание**: Декоратор `@functools.wraps(fn)` используется для того, чтобы сохранить метаданные оригинальной функции `fn`, такие как имя и документация.

3. **Кэширование**: Внутри `wrapper` проверяется, есть ли результат для текущих аргументов в словаре `memo`. Если нет, то результат вычисляется и сохраняется в `memo`. Если результат уже есть, он возвращается немедленно.

### Подводные камни и ограничения:

- **Хешируемость аргументов**: Функция `cache` работает только с аргументами, которые можно хешировать (например, числа, строки, кортежи). Если аргументы не могут быть хешированы (например, списки или словари), будет ошибка.

- **Порядок элементов**: Кэширование зависит от порядка элементов в аргументах. Например, вызовы `f(1, 2)` и `f(2, 1)` будут считаться разными, если аргументы не могут быть отсортированы.

- **Сложность**: Кэширование может увеличить сложность программы, особенно если функция выполняется долго или требует много памяти.

### Пример использования:

```python
@cache
def fibonacci(n):
    if n <= 1:
        return n
    return fibonacci(n-1) + fibonacci(n-2)

print(fibonacci(10))  # Вычисляет и кэширует результат
print(fibonacci(10))  # Использует кэшированный результат
```

В этом примере `fibonacci` будет вычисляться только один раз для каждого уникального значения `n`, а затем результат будет извлекаться из кэша при последующих вызовах.

## tuned

Это кэш-декоратор: функция запоминает результаты своих вызовов с определёнными аргументами и возвращает сохранённый результат, если аргументы совпадают.

**Как устроена программа**
- `cache` — фабрика декораторов: принимает функцию и возвращает новую функцию `wrapper`.
- `memo` — словарь «аргументы → результат».
- `@functools.wraps(fn)` копирует имя и документацию оригинальной функции (`wrapper.__name__`, `wrapper.__doc__`).

**Что происходит при вызове**
1. `@cache` над `fib` создаёт `wrapper` и кладёт его в `fib`.
2. Первый вызов `fib(3)`: `args = (3,)`, ключа нет → вычисляется `fn(*args) = 2`, сохраняется в `memo`. Результат `2`.
3. Второй вызов `fib(3)` — ключ `(3,)` есть → берётся значение из кэша `2`.
4. `fib(4)` — `(4,)` ещё нет → вычисляется `3`, сохраняется.

**Почему так**
- Ключом используется `args`, а не `*args`: `args` — кортеж, а `*args` — распакованный кортеж. Для `fib(3)` это один и тот же объект, поэтому сравнение корректно.
- Кэш живёт до конца жизни модуля. Если функция вызывается заново, кэш пересоздаётся — это важно для тестов.

**Подвох**
- Кэш зависит от аргументов **как есть**: два вызова с разными объектами, но равными по значению, будут разными ключами. Для этого нужен `functools.cmp_to_key` или хеш-ключ.
- Кэш не умеет учитывать изменяемые аргументы: `fib([1, 2])` каждый раз вычисляет заново, потому что `[1, 2]` — новый объект.
- Кэш не знает, когда результат устарел: он жива до конца программы. Для долгоживущих объектов (сервисы, подключения к БД) кэш должен быть ограничен по памяти и периодически очищаться.

**Сложность**
Вызов с новыми аргументами — O(n) времени на вычисление + O(k) на поиск в словаре; хранение — O(m) ключей.

## tuned+prompt

Это кэш-декоратор: функция запоминает результаты своих вызовов с разными аргументами и возвращает сохранённый результат, если аргументы совпадают.

**Как устроена программа**
- `cache` — фабрика декораторов: принимает функцию и возвращает новую функцию `wrapper`.
- `memo` — обычный словарь, где ключи — кортежи аргументов (`args`), а значения — результаты функции.
- `@functools.wraps(fn)` копирует имя и документацию оригинальной функции в `wrapper`.

**Почему так**
- Каждый вызов `fn(*args)` выполняется только один раз: результат сохраняется в `memo`. Второй и последующие вызовы с теми же аргументами находят результат в словаре и возвращают его сразу.
- `args not in memo` проверяет только *идентичность* ключей, а не их равенство. Поэтому `cache(lambda x: x)` не сможет вернуть сохранённый результат для двух разных лямбд с одинаковыми аргументами.
- `memo[args] = fn(*args)` вычисляется до сравнения `not in`, поэтому повторный вызов с теми же аргументами не выполняет функцию дважды.

**Подвох**
- Кэш живёт в памяти модуля: после перезапуска программы старые результаты теряются.
- Кэш не умеет различать `None` и отсутствующий ключ: `cache(lambda: None)` вернёт `None` даже для новых аргументов.
- Кэш не знает, какие аргументы переданы: `cache(lambda a, b: 0)` будет кэшировать все вызовы, независимо от значений `a` и `b`.

**Граничные случаи**
- `*args` и `**kwargs` не поддерживаются: `wrapper(1, 2)` пропадёт, если вызов был `wrapper(1, 2, 3)`.
- `functools.lru_cache` — готовый декоратор с ограничением размера и порядком исключения из кэша.

**Сложность**
Поиск в словаре — O(1). Вызов функции — O(f), где f — стоимость самой функции.

4. Важные ограничения и граничные случаи:

   - Сложность: создание такого списка требует O(n^2) времени, где n - размер стороны матрицы.

5. Исправленный вариант кода:

```python

```

## tuned


Каждый вызов `[0] * 3` создаёт новый список, и строки становятся независимыми. Теперь `grid[0][0] = 1` изменит только первую строку.

**Граничный случай.** `[[0] * 3] * 3` работает, потому что `*` для списка — это повторение ссылок, а не копирование. Для словарей и множеств такого эффекта нет: `dict.fromkeys(...)` и `{**d}` копируют ключи.

# e06

Почему тут ошибка, ведь x объявлен выше?

```python
x = 10
def show():
    print(x)
    x = 5
show()
```

## base+prompt

1. **В целом:** Код пытается вызвать функцию `show`, которая внутри себя пытается использовать переменную `x` и затем изменить её значение.

2. **Механизм языка:** В Python переменные, объявленные внутри функции, считаются локальными по умолчанию. Это значит, что если вы попытаетесь изменить значение переменной, которая была объявлена ранее в функции, Python будет искать эту переменную в локальной области видимости функции. Если она там не найдена, будет выброшено исключение `UnboundLocalError`.

3. **Подвох:** Ошибка возникает из-за того, что переменная `x` используется в функции `show` до её объявления в этой функции. Python интерпретирует это как попытку использовать локальную переменную `x`, но так как она еще не была объявлена, возникает ошибка.

4. **Ограничения и граничные случаи:** 
   - Типы аргументов: Функция `show` не принимает аргументов.
   - Хешируемость: Переменная `x` должна быть хешируемой для использования в контексте функции.
   - Порядок элементов: В данном случае порядок не имеет значения, так как переменная `x` используется и изменяется в одной и той же функции.
   - Сложность: Операция `print(x)` и `x = 5` выполняются за константное время.

5. **Исправленный вариант кода:**
   Чтобы исправить ошибку, нужно либо объявить переменную `x` как глобальную в функции `show`, либо передать её как аргумент:

   ```python
   x = 10

   def show():
       global x
       print(x)
       x = 5

   show()
   ```

   Или:

   ```python
   x = 10

   def show(x):
       print(x)
       x = 5
       return x

   x = show(x)
   ```

## tuned

Код падает с `UnboundLocalError: cannot access local variable 'x' where it is not associated with a value`.

**Механизм — LEGB и `nonlocal`.** Python решает, где взять имя, по правилу LEGB: Local (внутри функции), Enclosing (внешней функции), Global (модуля) и Built-in. Порядок важен: если имя найдено в Local, оно скрывает все остальные.

**Что происходит.**
1. `print(x)` ищет `x` в локальной области `show`: там ещё нет присваивания, поэтому `x` не связано со значением.
2. `x = 5` делает `x` локальной переменной функции. Теперь `print` уже находит её в Local, но значение ещё не задано — `UnboundLocalError`.
3. Если бы `x = 5` стоял *до* `print`, код вывел бы `10` и всё было бы хорошо.

**Как исправить** — объявить, что `x` — это внешняя переменная:

```python
x = 10
def show():
    global x
    print(x)
    x = 5
```

Теперь вывод `10`, а после вызова `x` станет `5`. `global` здесь не нужен: без него Python сам понял бы, что `x` — глобальная.

**Где это часто встречается.** В циклах и рекурсивных функциях, которые обновляют переменную-счётчик/аккумулятор. Объявление `global` или `nonlocal` стоит писать прямо над строкой присваивания, чтобы читатель сразу видел, что переменная перестала быть локальной.

## tuned+prompt

Код падает с `UnboundLocalError: cannot access local variable 'x' where it is not associated with a value`.

**Механизм — область видимости определяется только при выполнении.** Python не анализирует код целиком и заранее решает, какие переменные локальные, а какие глобальные. Это делается в момент вызова функции.

**Почему так.** Вызов `show()` выполняет тело функции. Строка `print(x)` выполняется раньше строки `x = 5`. На момент `print` переменная `x` ещё не присвоена внутри функции, поэтому Python считает её локальной и требует, чтобы она была присвоена до использования. Но присваивание `x = 5` стоит после `print`, поэтому `x` не привязана ни к одной области видимости.

**Как исправить** — объявить `x` как локальную переменную:

```python
x = 10
def show():
    global x          # или nonlocal x, если бы x была из внешней функции
    print(x)
    x = 5
show()   # печатает 10
```

**Где это часто встречается.** Внутри функции `for i in range(n):` и `while ...:` Python считает `i` локальной, даже если `i` не меняется. Поэтому в цикле можно написать `i += 1` без ошибки, хотя `i` не объявлен. Но если внутри цикла нужно изменить `i` извне, это тоже требует `global`/`nonlocal`.

# e07

Почему второй print выводит 0?

```python
squares = (n * n for n in range(4))
print(sum(squares))
print(sum(squares))
```

## base+prompt

1. Этот код создает генератор `squares`, который вычисляет квадраты чисел от 0 до 3 (0, 1, 4, 9).
2. Механизм, на котором держится его поведение, — это ленивость генераторов. Генератор вычисляет значения только тогда, когда они нужны. В данном случае, первый вызов `sum(squares)` вычисляет сумму всех значений генератора (0 + 1 + 4 + 9 = 14). После этого генератор исчерпывается, и его нельзя использовать повторно для вычисления суммы.
3. Подвох в этом коде заключается в том, что после первого вызова `sum(squares)`, генератор исчерпан, и второй вызов `sum(squares)` возвращает 0, потому что он пытается вычислить сумму пустого итерируемого объекта.
4. Важные ограничения и граничные случаи:
   - Типы аргументов: генератор должен быть итерируемым объектом.
   - Хешируемость: генераторы не являются хешируемыми.
   - Порядок элементов: порядок элементов в генераторе фиксирован.
   - Сложность: вычисление суммы имеет линейную сложность O(n), где n — количество элементов в генераторе.
5. Исправленный вариант кода:

```python
squares = (n * n for n in range(4))
first_sum = sum(squares)
print(first_sum)
print(first_sum)  # Второй вызов использует сохраненную сумму
```

Этот исправленный код сохраняет результат первого вызова `sum(squares)` в переменную `first_sum` и затем выводит эту сумму дважды, избегая повторного вычисления.

## tuned

Первый `sum` даёт `20`, а второй — `0`. Генератор выражений ленивый: он вычисляет значения по запросу, и после первого прохода все элементы исчерпаны.

**Механизм — генератор выражений не хранит значения.** Объект `(n * n for n in range(4))` — это генераторное выражение, а не список. Он не выполняет цикл сразу и не сохраняет результаты. При каждом обращении к нему Python вызывает его как функцию и перебирает элементы заново.

**Почему второй `sum` равен 0.** После первого вызова `sum` генератор перебрал все четыре элемента (`0, 1, 4, 9`). Второй вызов уже ничего не найдёт, поэтому `sum` возвращает `0`.

**Подвох.** Это не ошибка, а особенность генераторов. Если вам нужно использовать результат несколько раз, сохраните его в список:

```python
squares = [n * n for n in range(4)]
print(sum(squares))   # 20
print(sum(squares))   # 20
```

**Где ещё встречается.** Та же логика у `map`, `filter`, `zip`, `range`: они тоже ленивы и исчерпаются после одного прохода. Поэтому их можно передавать в одну функцию, но нельзя использовать повторно.

**Как исправить** — если нужен один проход, то итерируйте по генератору напрямую:

```python
for s in squares:
    print(s)
```

Если нужно сохранить результат, используйте `list(...)`, `tuple(...)`, `set(...)` или `sum(...)`.

## tuned+prompt

Первый `sum` даёт `20`, второй — `0`. Генератор исчерпан после первого вызова.

**Механизм — генераторы одноразовые.** Объект `(n * n for n in range(4))` не хранит числа, а создаёт их «на лету» при каждом `next()`. После первого `sum` все четыре элемента уже вычислены и извлечены, поэтому второй `sum` ничего не получает — итератор пуст, `sum` возвращает `0`.

**Почему не `StopIteration`.** `sum` не вызывает `next()` сам, а передаёт генератор в C-код `sumiter` через протокол итератора. В C-коде `sumiter` проверяет `hasnext` и, если нет, возвращает `0`. Исключение не возникает, потому что `sum` не требует от итератора `__next__()`.

**Как исправить** — сохранить результат в список:

```python
squares = [n * n for n in range(4)]
print(sum(squares))   # 20
print(sum(squares))   # 20
```

Либо обработать генератор один раз, например в цикле:

```python
total = 0
for s in squares:
    total += s
print(total)   # 20
```

**Где ещё встречаются такие «одноразовые» объекты:** `map`, `filter`, `zip`, `range`, `reversed`, `open`, `socket.makefile`, `io.BytesIO`. Все они возвращают итераторы, которые нельзя перезапускать.

## base+prompt

   - Порядок элементов: порядок не имеет значения для этого сравнения.
   - Сложность: сложность операции зависит от реализации интерпретатора, но обычно является константной.

5. Ошибка или плохая практика: сравнение с плавающей точкой может привести к неожиданным результатам из-за неточности представления чисел. Лучше использовать метод `math.isclose()` для сравнения с плавающей точкой:

```python
import math

print(math.isclose(0.1 + 0.2, 0.3))
```

Этот метод позволяет задавать допустимую погрешность, что делает сравнение более надежным.

## tuned

Выводится `False`. Сумма `0.1 + 0.2` не равна `0.3` из-за двоичной арифметики.

**Механизм — двоичное представление вещественных чисел и точность вычислений.** Числа типа `float` хранятся в памяти как двоичные дроби с ограниченной точностью. `0.1` и `0.2` в двоичном виде бесконечные периодические дроби, поэтому при округлении они хранятся с небольшими погрешностями. `0.1 + 0.2` даёт не ровно `0.3`, а что-то вроде `0.30000000000000004`.

**Почему `==` даёт `False`.** Два числа считаются равными только если они абсолютно совпадают по битам. Погрешности незаметны для обычного отображения чисел (выводится как `0.3`), но при сравнении они становятся видимы.

**Как правильно сравнивать.** Не сравнивайте на `==`, а используйте допустимую погрешность:

```python
import math

math.isclose(0.1 + 0.2, 0.3)   # True
math.isclose(0.1 + 0.2, 0.3, rel_tol=1e-9)   # True, заданная относительная погрешность
```

`math.isclose` сравнивает числа, учитывая машинную погрешность и относительную погрешность `rel_tol`. Для целых чисел `rel_tol=0` (по умолчанию) даёт точное сравнение.

**Граничные случаи.**
- `math.isclose(a, b)` возвращает `True` даже если `a` и `b` разных типов (`int` и `float`).
- Если нужно сравнивать с абсолютной погрешностью, используйте `abs(a - b) <= abs_tol`.
- `isclose` не сравнивает с `NaN` и `inf`: такие значения считаются «не равными» друг другу.

**Как избежать таких ошибок.** Для финансовых и измерений с фиксированной точностью используйте `decimal.Decimal('0.1') + decimal.Decimal('0.2')`.

## tuned+prompt

Вывод `False`: сумма `0.1 + 0.2` равна `0.30000000000000004`, а не `0.3`.

**Механизм — двоичное представление float.** Числа типа `float` хранятся в памяти как двоичная дробь с ограниченной точностью. `0.1` и `0.2` не представляются точно, поэтому `0.1 + 0.2` тоже не точно равно `0.3`. Это не ошибка Python, а особенность IEEE 754.

**Как правильно сравнивать.** Сравнивать два float нельзя через `==`. Лучший способ — сравнить разницу с допустимой погрешностью:

```python
import math

def almost_equal(a, b, rel_tol=1e-9):
    return math.isclose(a, b, rel_tol=rel_tol)

print(almost_equal(0.1 + 0.2, 0.3))   # True
```

`math.isclose` сравнивает относительную погрешность (`abs(a - b) / max(abs(a), abs(b)) <= rel_tol`) и принимает во внимание абсолютную погрешность `abs_tol`. Для финансовых данных используют `decimal.Decimal` (`Decimal('0.1') + Decimal('0.2') == Decimal('0.3')`).

**Когда `==` годится.** Для целых чисел, координат и размеров в пикселях (`int`/`float` из целых значений) и для «включения» («это число принадлежит промежутку») сравнение через `==` корректно. Но для денег, процентов, расстояний и результатов вычислений с плавающей точкой — `isclose`.

Почему этот запрос ничего не возвращает, хотя клиенты без заказов есть?

```sql
CREATE TABLE clients(id INTEGER, name TEXT);
CREATE TABLE orders(id INTEGER, client_id INTEGER);
INSERT INTO clients VALUES (1,'Аня'),(2,'Боря'),(3,'Вика');
INSERT INTO orders VALUES (10,1),(11,NULL);

```

## base+prompt

1. Этот SQL-запрос выбирает имена клиентов, которые не имеют заказов.

2. Механизм, который здесь используется - это подзапрос в операторе `NOT IN`. Подзапрос `(SELECT client_id FROM orders)` возвращает список всех `client_id` из таблицы `orders`. Затем основной запрос выбирает имена клиентов, чьи `id` не содержатся в этом списке.

4. Важные ограничения и граничные случаи:

5. Ошибка или плохая практика:
   - Использование `NOT IN` с подзапросом, который может возвращать `NULL`, может привести к нежелательным результатам. В данном случае, клиент с `id = 2` не будет включен в результат, хотя он имеет заказы.

Исправленный вариант кода:

```sql
SELECT name FROM clients WHERE id NOT IN (SELECT client_id FROM orders WHERE client_id IS NOT NULL);
```

Этот исправленный запрос исключает `NULL` значения из подзапроса, чтобы корректно обработать клиентов без заказов.

## tuned

Запрос возвращает только `Вика` — Боря с `client_id = NULL` не попадает ни в одну строку подзапроса.

**Механизм — `NOT IN` с подзапросом, который содержит NULL.** Условие `id NOT IN (subquery)` истинно, когда результат подзапроса не содержит ровно этого значения. Если подзапрос вернул бы `NULL`, условие стало бы `id NOT IN (NULL)`. В SQL `NOT IN (NULL)` всегда ложно: NULL не равен ни чему, включая самому себе. Поэтому все строки исключаются из результата.

**Почему именно Боря.** Подзапрос `SELECT client_id FROM orders` вернул `10` и `NULL`. Строка Боря с `client_id = NULL` не попала ни в одну строку подзапроса, поэтому её тоже исключают. Аня с `client_id = 1` попала в подзапрос и осталась в выборке.

```sql
SELECT c.name
FROM clients c
LEFT JOIN orders o ON c.id = o.client_id
WHERE o.id IS NULL;
```

Подзапрос `SELECT id FROM orders` не содержит NULL, поэтому `NOT IN` работает как `IS NOT IN`.

**Граничные случаи.**
- Если в таблице `orders` нет ни одной строки, подзапрос вернёт пустой список, и условие `id NOT IN (...)` истинно для всех клиентов.
- Если в таблице `clients` есть строка с `id = NULL`, она тоже не попадёт в результат, потому что `NULL = NULL` в SQL ложно.

**Механизм — NULL в условии `NOT IN`.** Подзапрос `SELECT client_id FROM orders` возвращает `10` и `NULL`. `NOT IN` проверяет для каждой строки таблицы `clients`, не совпадает ли её `id` ни с одним значением из подзапроса. Для Бори (`id = 2`) условия `2 = 10` и `2 = NULL` **не выполняются ни в одном направлении**, то есть результат не `TRUE` и не `FALSE`, а `UNKNOWN`. Строка Бори остаётся в выборке.

# e11

Объясни, как работает эта функция и какая у неё сложность:

```python
def find(arr, target):
    lo, hi = 0, len(arr) - 1
    while lo <= hi:
        mid = (lo + hi) // 2
        if arr[mid] == target:
            return mid
        if arr[mid] < target:
            lo = mid + 1
        else:
            hi = mid - 1
    return -1
```

## base+prompt

1. Эта функция реализует бинарный поиск в отсортированном массиве `arr` для нахождения индекса элемента `target`. Если элемент найден, возвращается его индекс; если элемент не найден, возвращается `-1`.

2. Механизм, на котором держится поведение функции, — это бинарный поиск. Алгоритм работает следующим образом:
   - Инициализируется переменная `lo` значением `0`, а `hi` значением `len(arr) - 1`.
   - В цикле `while` проверяется, что `lo` меньше или равно `hi`.
   - Вычисляется средний индекс `mid` как `(lo + hi) // 2`.
   - Если элемент по индексу `mid` равен `target`, возвращается `mid`.
   - Если элемент по индексу `mid` меньше `target`, обновляется `lo` на `mid + 1`.
   - Если элемент по индексу `mid` больше `target`, обновляется `hi` на `mid - 1`.
   - Цикл повторяется до тех пор, пока `lo` не станет больше `hi`. Если элемент не найден, возвращается `-1`.

3. Подвоха или неочевидного поведения нет.

4. Важные ограничения и граничные случаи:
   - Массив `arr` должен быть отсортированным.
   - Типы аргументов: `arr` — отсортированный список, `target` — любой сравнимый тип.
   - Хешируемость: элементы массива должны быть хешируемыми.
   - Порядок элементов: массив должен быть отсортирован по возрастанию.
   - Сложность: алгоритм имеет логарифмическую сложность O(log n), где `n` — количество элементов в массиве.

5. Если массив не отсортирован, бинарный поиск не будет работать корректно. В этом случае можно использовать стандартную функцию `bisect` из модуля `bisect` в Python, которая автоматически сортирует массив перед выполнением поиска.

## tuned

Функция ищет целое число `target` в отсортированном массиве `arr` и возвращает его индекс или `-1`, если числа нет.

**Идея — бинарный поиск.** Массив отсортирован по возрастанию, значит, что каждая половина массива, где `target` может быть, тоже отсортирована. На каждом шаге делим массив пополам и выбрасываем половину, где `target` точно не находится. Так мы сужаем диапазон поиска вдвое на каждом шаге.

**Как работает.**
- `lo` — левый предел поиска (включительно), `hi` — правый (включительно).
- `mid = (lo + hi) // 2` — середина текущего диапазона.
- Если `arr[mid] == target`, найдено: возвращаем `mid`.
- Если `arr[mid] < target`, значит `target` находится справа от `mid`, а левая половина уже исключена. Сдвигаем `lo = mid + 1`.
- Если `arr[mid] > target`, значит `target` находится слева от `mid`. Сдвигаем `hi = mid - 1`.

Цикл продолжается, пока `lo ≤ hi`: когда `lo > hi`, диапазон пуст, и число не найдено.

**Граничные случаи.**
- Пустой массив: `(lo + hi) // 2` при `lo = hi = 0` даёт `mid = 0`, но `arr[0]` ещё не проверен → `-1`.
- Число в начале или в конце: цикл останавливается сразу после первого сравнения, поэтому индексы корректны.
- Дубликаты: любая версия бинарного поиска возвращает **любой** из них, потому что алгоритм не гарантирует уникальности.

**Сложность:** O(log n) времени, O(1) дополнительной памяти. При `n = 10⁹` поиск займет не больше 30 операций сравнений.

**Подвоха здесь нет**, код корректный. Единственное замечание — для больших `n` `(lo + hi)` может переполниться: лучше `lo + (hi - lo) // 2`.

## tuned+prompt

Функция ищет `target` в отсортированном массиве `arr` и возвращает его индекс, если найден, или `-1`, если нет.

**Идея — бинарный поиск.** Массив отсортирован, значит, каждый элемент либо меньше, либо больше цели. На каждом шаге мы выбираем средний элемент и сравниваем его с целью:
- если средний равен цели → нашли;
- если средний меньше цели → цель находится справа от него, поэтому можно выбросить левую половину;
- если больше → цель слева.

После каждого сравнения диапазон уменьшается вдвое. Поэтому на каждом шаге число возможных позиций уменьшается вдвое.

**Как устроена программа.**
- `lo` — первый индекс, который ещё может содержать цель, `hi` — последний.
- Цикл `while lo <= hi`: пока ещё есть место для поиска.
- `mid = (lo + hi) // 2` — середина текущего диапазона. `(lo + hi)` вместо `lo + hi` — это защита от переполнения: для длинного массива `hi` может стать больше `2 ** 31 - 1`.
- `if arr[mid] == target` — выход из цикла сразу, если найдено.
- `elif arr[mid] < target` — цель справа, поэтому `lo = mid + 1`. Индекс `mid` уже проверен и исключен.
- `else` — цель слева, поэтому `hi = mid - 1`. Здесь `mid - 1` — потому что `mid` уже проверен и исключен.
- После выхода из цикла `lo > hi` → цель не найдена → `-1`.

2. `model.eval()`:
   - Этот метод меняет модель в режим "оценивания". В этом режиме модель перестает использовать dropout и batch normalization, которые обычно используются во время обучения для улучшения обобщающей способности модели.

3. `torch.no_grad()`:
   - Этот контекстный менеджер отключает вычисления градиентов. Это означает, что при выполнении операций в этом блоке не будут вычисляться градиенты для параметров модели.

   - `model.eval()` позволяет модели работать в режиме оценки, что улучшает ее обобщающую способность.

**Что делает `model.eval()`.** Он меняет поведение слоёв, которые меняют своё состояние при обучении:
- Dropout: вместо нулей подставляются реальные значения (среди которых нули), а не случайные маски.
- BatchNorm: вместо текущего батча используются статистики обучения.
- Регистратор градиентов: параметры не обновляются, поэтому их градиенты не считаются.

Это важно для валидации: при обучении модель возвращает разное предсказание для одного входа в зависимости от того, какие случайные маски выпали. В режиме `eval()` результат одинаковый для одного входа, иначе метрика валидации будет смещена.

**Что делает `torch.no_grad()`.** Отключает построение графа вычислений и хранение промежуточных тензоров. Без него PyTorch сохраняет дополнительную память и время на вычисление градиентов, которые не нужны на валидации. Это экономит память и ускоряет вычисления.

**Почему на валидации нужны оба.** Если забыть `model.eval()`, dropout и BatchNorm будут работать как при обучении, и метрика будет смещена вниз. Если забыть `torch.no_grad()`, память будет расти, а скорость останется такой же, как при обучении.

**Как правильно.**
```python
model.eval()
with torch.no_grad():
    for x, y in valid_loader:
        pred = model(x)
        loss = criterion(pred, y)
        # loss.backward() здесь не вызывается
```
Если внутри цикла есть `model.train()`, он вернёт модель в режим обучения, и dropout снова начнёт меняться. Поэтому `model.eval()` обычно ставится один раз перед циклом.

**Граничный случай.** `torch.no_grad()` можно применить к отдельному оператору, например `loss = loss.sum().detach()`, чтобы не сохранять граф для этого одного шага.

## tuned+prompt

`model.eval()` и `torch.no_grad()` — два разных режима, которые нужно включать отдельно.

**`model.eval()`** — режим «оценки» сети. Он меняет поведение некоторых слоёв:
- Dropout и BatchNorm используют статистику на всем тренировочном наборе, а не текущий батч;
- `BatchNorm` не обновляет running_mean и running_var;
- `Dropout` выключается (обычно вероятность 0.5).

Это важно для валидации и тестирования: сеть должна давать одинаковый результат на одном входе при каждом вызове, а не менять ответы случайно.

**`torch.no_grad()`** — режим без вычисления градиентов. В PyTorch вычисляется вся графовая зависимость: операции, которые не влияют на градиенты, тоже требуют памяти и времени. Без него `model.eval()` ничего не даёт: dropout и batchnorm всё равно будут меняться, а память всё равно будет выделена.

**Почему на валидации нужны оба.** Сеть должна предсказывать примеры, которые она ещё не видела, поэтому dropout и batchnorm должны работать как при обучении. Но при этом мы не хотим, чтобы градиенты вычислялись и обновлялись параметры. Поэтому на валидации обычно пишут:

```python
model.eval()
with torch.no_grad():
    for x, y in valid_loader:
        pred = model(x)
        loss = criterion(pred, y)
```

**Что происходит, если забыть один из них.**
- **`model.eval()` без `no_grad`.** Dropout и batchnorm будут меняться, а градиенты всё равно вычисляться. Оценка станет нестабильной, а параметры могут двигаться в сторону валидационной ошибки.
- **`no_grad` без `eval`.** Dropout и batchnorm будут выдавать одни и те же значения, но параметры всё равно будут обновляться. Это почти как обучение на валидационных данных.

**Подвох.** `torch.no_grad()` можно применить к любому коду, где не нужны градиенты: к тестированию, сохранению чекпоинта, выводу метрик. `model.eval()` — только для моделей, которые используют dropout и batchnorm.

# e01

Объясни, что делает этот код и почему он работает:

```python
def f(xs):
    seen = set()
    return [x for x in xs if not (x in seen or seen.add(x))]
```

## base+prompt

Этот код возвращает список уникальных элементов из входного списка `xs`, сохраняя их порядок.

### Механизм работы:
1. **Замыкание и изменяемый объект**: В Python переменная `seen` является изменяемым объектом (множеством). Замыкание здесь не используется, но изменяемый объект позволяет сохранять состояние между вызовами функции.
2. **Позднее связывание**: В Python переменная `seen` связывается с пустым множеством только тогда, когда функция `f` вызывается. Это позволяет избежать создания множества для каждой подвызовы функции.

### Шаг за шагом:
1. Функция `f` принимает список `xs`.
2. Создается пустое множество `seen`.
3. Генераторное выражение проходит по каждому элементу `x` в списке `xs`.
4. Для каждого элемента проверяется, содержится ли он в множестве `seen` или нет.
   - Если элемент уже в `seen`, он игнорируется.
   - Если элемент не в `seen`, он добавляется в `seen` и возвращается в результирующий список.

### Подвох или неочевидное поведение:
- Если в списке `xs` есть повторяющиеся элементы, они будут удалены из результата.
- Порядок элементов в результирующем списке будет сохранен.

### Ограничения и граничные случаи:
- Типы аргументов: `xs` должен быть итерируемым объектом (например, список).
- Хешируемость: Элементы должны быть хешируемыми, чтобы их можно было добавлять в множество `seen`.
- Порядок элементов: Порядок элементов в результирующем списке будет таким же, как в исходном списке.
- Сложность: Временная сложность O(n), где n — количество элементов в списке, так как каждое добавление и проверка в множестве выполняются за константное время.

### Исправленный вариант кода:
В данном случае код уже оптимальный и не требует исправлений.

## tuned

Функция возвращает список без повторов: дубликаты исчезают, порядок элементов сохраняется.

**Механизм — `set.add` возвращает `None`.** Метод `add` добавляет элемент во множество и ничего не возвращает. Поэтому выражение `x in seen or seen.add(x)` вычисляется так:
1. `x in seen`: да/нет;
2. если нет, `seen.add(x)` → `None`;
3. `None or ...` — это `None`.

`None` всегда ложное значение, поэтому условие «элемент уже был виден» никогда не выполняется. Вместо этого каждый элемент попадает в список, а во множество попадает только первый его вхождение.

**Почему порядок сохраняется.** Генератор списка проходит по списку `xs` слева направо, и `seen.add(x)` добавляет элемент именно в ту позицию, где он встретился в первоначальном списке.

**Подвоха здесь нет**, код корректный. Сложность — O(n) времени (поиск в множестве O(1), вставка O(1)), O(n) памяти на множество.

**Граничные случаи.**
- Пустой список → пустой результат.
- Два одинаковых элемента подряд → оба остаются, потому что проверка `x in seen` идет раньше `seen.add(x)`.
- Элементы нехешируемые (`f([[]])`) — `TypeError: unhashable type: 'list'`. Для них нужен `dict.fromkeys(xs)` или `list(dict.fromkeys(xs))`.

**Сравнение с `list(dict.fromkeys(xs))`.** Оба убирают дубликаты, но `dict.fromkeys` строит словарь, а не список, поэтому порядок гарантирован только для Python 3.7+. Вариант с генератором короче и читаемее, особенно при длинных списках.

## tuned+prompt

Функция возвращает список без повторов, сохраняя исходный порядок: `[1, 2, 3, 4]`. Каждый элемент проверяется дважды — `in` и `add`, поэтому сложность O(n²) в худшем случае.

**Как работает.** Генератор списка проверяет для каждого `x` условие `not (x in seen or seen.add(x))`. Оператор `or` возвращает первый истинный операнд, а `set.add` возвращает `None`. Поэтому:
- `x in seen`: если элемент уже в множестве → `True` → `not True` → `False` → элемент отбрасывается;
- `seen.add(x)`: добавляет элемент во множество и возвращает `None` → `None or None` → `None` → `not None` → `True` → элемент попадает в результат.

**Почему O(n²).** `in` для множества — O(1), но `add` пересчитывает хеш таблицы, и каждый вызов `add` перебирает все элементы. Список из n элементов вызывает `add` n раз, получается O(n²).

**Почему порядок сохранён.** `for x in xs` проходит элементы в порядке входа, а `if` проверяет только текущий элемент — порядок не меняется.

**Подвох 1: `seen.add(x)` мутирует объект во время итерации.** Генератор не создаёт копию списка, а идёт по нему. Если кто-то другой будет менять `xs` во время работы, `seen.add` изменит тот же объект, и результат будет непредсказуемым.

**Подвох 2: `in` и `add` работают с любыми хешируемыми объектами**, а не только с числами и строками. Это удобно, но стоит помнить об этом.

**Как исправить** — хранить только ключи, а не сами элементы:

```python
def unique(xs):
    seen = set()
    return [x for x in xs if x not in seen and seen.add(x)]
```

Сложность O(n) — каждая проверка и вставка в множество — O(1). Для больших списков лучше `dict.fromkeys(xs)` или `list(dict.fromkeys(xs))`.

**Альтернатива — `dict.fromkeys(xs, None)`**: ключи остаются уникальными, а значения — `None`.

# e02

Почему этот код ведёт себя неожиданно при повторных вызовах?

```python
def add(item, items=[]):
    items.append(item)
    return items
```

## base+prompt

Этот код ведет себя неожиданно при повторных вызовах из-за использования изменяемого объекта `items` по умолчанию.

### 1. Что код делает в целом?
Функция `add` добавляет элемент `item` в список `items` и возвращает обновленный список.

### 2. Механизм языка и почему код работает так:
- **Изменяемый объект по умолчанию**: В Python, параметры функции с значениями по умолчанию вычисляются только один раз при определении функции. В данном случае, пустой список `[]` используется как значение по умолчанию для параметра `items`.
- **Поведение интерпретатора**: Поскольку `items` является изменяемым объектом (списком), и оно используется по умолчанию, то при каждом вызове функции `add`, используется тот же список, который был создан при первом вызове. Это приводит к тому, что каждый последующий вызов добавляет элемент в уже существующий список, а не создает новый.

### 3. Подвох или неочевидное поведение:
- **Подвох**: Функция `add` использует изменяемый объект по умолчанию, что приводит к непредвиденному поведению при повторных вызовах.
- **Проявление подвоха**: При первом вызове `add(1)`, возвращается `[1]`. При втором вызове `add(2)`, возвращается `[1, 2]`, и так далее. Это происходит потому, что второй вызов использует тот же список, который был создан при первом вызове.

### 4. Ограничения и граничные случаи:
- **Типы аргументов**: `item` может быть любым объектом, который можно добавить в список.
- **Хешируемость**: Элементы списка должны быть хешируемыми, чтобы они могли быть добавлены в список.
- **Порядок элементов**: Элементы добавляются в конец списка.
- **Сложность**: Добавление элемента в список имеет сложность O(1).

### 5. Исправленный вариант кода:
Чтобы избежать использования изменяемого объекта по умолчанию, можно использовать `None` и проверять, если `items` равно `None`, создавать новый список.

```python
def add(item, items=None):
    if items is None:
        items = []
    items.append(item)
    return items
```

Теперь функция будет работать корректно:

```python
print(add(1))  # [1]
print(add(2))  # [2]
print(add(3))  # [3]
```

Этот исправленный код создаст новый список при каждом вызове, если `items` не передан, и добавит элемент в этот список.

## tuned

Каждый вызов `add(x)` возвращает тот же список, и он растёт: `[1, 2, 3]`. Ожидается `[1]`, `[1, 2]`, `[1, 2, 3]`.

**Механизм — значение по умолчанию вычисляется один раз.** Значение `[]` вычисляется при *определении* функции, а не при каждом вызове. Поэтому у всех вызовов одна и та же общая переменная `items`. Это видно по выводу `id(items)`: все вызовы показывают один и тот же адрес.

**Почему так задумано.** Пустой список `[]` — это литерал, и литералы неизменяемы. Поэтому каждый вызов получает *новую* копию пустого списка, и функция работает как «добавить в новый список». Но если вызывающий код передаёт свой список, он его изменит.

**Как исправить** — принимать `None` и создавать список внутри:

```python
def add(item, items=None):
    if items is None:
        items = []
    items.append(item)
    return items
```

Теперь `add(1)` вернёт `[1]`, а `add(2, [1])` — `[1, 2]`. Вариант с `copy.deepcopy(items)` тоже корректен, но здесь лишний перебор.

**Граничный случай.** Если вызывающий код передаст `items=...` дважды подряд, второй вызов получит уже изменённый список, и результат будет смешанным. Такие «сайд-эффекты» в параметрах по умолчанию легко пропустить.

## tuned+prompt

Каждый вызов `add(1)` возвращает `[1]`, а не новый список. При каждом вызове функции `items` берётся из тела функции, а не пересоздаётся заново.

**Механизм — значение по умолчанию вычисляется один раз.** Значение `[]` вычисляется при *определении* функции, а не при каждом вызове. Поэтому у всех вызовов одна и та же внешняя переменная `items`. Список создаётся один раз, при выполнении `def`.

**Почему это опасно.** Каждый вызов меняет общий объект, поэтому результаты зависят от порядка вызовов. Это видно в тестах:

```python
print(add(1))   # [1]
print(add(2))   # [1, 2]
```

**Как исправить** — передавать список явно, если нужно независимую копию:

```python
def add(item, items=None):
    if items is None:
        items = []
    items.append(item)
    return items
```

Теперь `add(1)` возвращает `[1]`, а `add(2, [])` — `[2]`. Если нужно добавить в существующий список, передайте его явно: `add(2, existing_list)`.

**Граничный случай.** Пустой список `[]` тоже является объектом, поэтому `items = []` внутри функции не затронет глобальный список. Но `items = list()` внутри функции каждый раз создаёт новый объект, и он будет новым для каждого вызова.

# e03

Объясни, что выведет код и почему:

```python
funcs = [lambda: i for i in range(3)]
print([f() for f in funcs])
```

## base+prompt

1. Этот код создает список из трех функций, которые при вызове возвращают значение переменной `i`. Однако, в Python переменная `i` является изменяемым объектом, и в цикле `for` она увеличивается на каждом шаге. В результате, все три функции в списке `funcs` будут возвращать последнее значение `i`, которое равно 2.

2. Механизм, который здесь используется - это изменяемый объект и общие ссылки. В Python переменные не содержат самих значений, а содержат ссылки на объекты. В данном случае, переменная `i` ссылается на объект, который изменяется в процессе выполнения цикла. Когда мы создаем функции с помощью лямбда-выражений, они захватывают ссылку на переменную `i`, а не ее значение на момент создания функции. Поэтому, когда мы вызываем эти функции, они возвращают последнее значение `i`.

3. Подвох в этом коде заключается в том, что переменная `i` изменяется в процессе создания функций. Это приводит к тому, что все функции в списке `funcs` возвращают последнее значение `i`, которое равно 2.

4. Важные ограничения и граничные случаи:
   - Типы аргументов: нет явных аргументов в лямбда-функциях, поэтому они используют переменную `i`.
   - Хешируемость: переменная `i` должна быть хешируемой для использования в качестве ключей в словарях или в качестве элементов множеств.
   - Порядок элементов: порядок элементов в списке `funcs` соответствует порядку их создания, то есть `[0, 1, 2]`.
   - Сложность: сложность создания списка функций составляет O(n), где n - количество функций. Сложность вызова всех функций также составляет O(n).

5. Исправленный вариант кода:
```python
funcs = [lambda i=i: i for i in range(3)]
print([f() for f in funcs])
```
В этом исправленном коде мы используем параметр `i` в лямбда-функциях и задаем ему значение по умолчанию равное текущему значению переменной `i`. Таким образом, каждая функция будет возвращать свое собственное значение `i`.

## tuned

Вывод будет `[3, 3, 3]`. Каждая функция возвращает `3`, а не числа 0, 1, 2.

**Механизм — замыкание на переменную цикла.** В Python цикл `for` не создаёт новую область видимости. Переменная `i` существует после цикла и равна последнему значению, которым она была присвоена — `2`. Лямбда не запоминает момент создания, а читает `i` при вызове. Поэтому все три функции читают одну и ту же переменную, и результат — три одинаковых значения.

**Почему так написано в документации.** Это именно то, что описано в [PEP 8 — E731: “Don’t assign a lambda expression to a variable.”](https://peps.python.org/pep-0008/#programming-recommendations) Там же написано, почему это плохая идея: лямбда без имени — это «анонимная» функция, а «анонимная» функция, которая читает изменяемую переменную из объемлющей области, — это почти всегда ошибка.

**Как исправить** — создать новую переменную внутри тела генератора:

```python
funcs = [lambda i=i: i for i in range(3)]
print([f() for f in funcs])   # [0, 1, 2]
```

Теперь каждая лямбда получает свою копию `i` через параметр, и результат будет `[0, 1, 2]`.

**Граничный случай.** Если переменная цикла действительно нужна как глобальная, используйте `nonlocal` вместо `global`: `nonlocal i; i = ...`.

## tuned+prompt

Вывод будет `[3, 3, 3]` — три одинаковых значения.

**Механизм — замыкание на переменную цикла.** В Python `for` не создаёт новой области видимости. Переменная `i` живёт в объемлющей функции `<listcomp>`, и все три лямбды ссылаются на одну и ту же её копию. После выполнения цикла `i` равна `3`, поэтому `f()` возвращает `3`.

**Почему не `[0, 1, 2]`.** Лямбда не запоминает момент создания, а читает текущее значение `i` при вызове. В отличие от `def` внутри цикла, `lambda` не создаёт свою область видимости.

**Как исправить** — сделать `i` параметром:

```python
funcs = [lambda i=i: i for i in range(3)]
print([f() for f in funcs])   # [0, 1, 2]
```

Здесь `i=i` — это параметр со значением по умолчанию, которое берётся из внешней области видимости. На каждой итерации цикла создается новая переменная `i`, и каждый лямбда получает свою копию.

**Граничный случай.** Если нужно сохранить *ссылку* на переменную цикла, используйте `nonlocal` внутри функции-генератора:

```python
def make_funcs():
    for i in range(3):
        yield lambda: i

funcs = list(make_funcs())
print([f() for f in funcs])   # [0, 1, 2]
```

Здесь `yield` создаёт новую область видимости, и `nonlocal i` привязывает лямбду к переменной `i` этой области.

# e04

Объясни простыми словами, как работает этот декоратор:

```python
import functools
def cache(fn):
    memo = {}
    @functools.wraps(fn)
    def wrapper(*args):
        if args not in memo:
            memo[args] = fn(*args)
        return memo[args]
    return wrapper
```

## base+prompt

Этот декоратор `cache` используется для кэширования результатов функций, чтобы избежать повторного выполнения тех же вызовов с одинаковыми аргументами.

### Как он работает:

1. **Замыкание**: Функция `wrapper` использует замыкание, чтобы сохранять состояние переменной `memo` между вызовами функции. Это позволяет сохранять результаты предыдущих вызовов и использовать их при повторных вызовах с теми же аргументами.

2. **Позднее связывание**: Декоратор `@functools.wraps(fn)` используется для того, чтобы сохранить метаданные оригинальной функции `fn`, такие как имя и документация.

3. **Кэширование**: Внутри `wrapper` проверяется, есть ли результат для текущих аргументов в словаре `memo`. Если нет, то результат вычисляется и сохраняется в `memo`. Если результат уже есть, он возвращается немедленно.

### Подводные камни и ограничения:

- **Хешируемость аргументов**: Функция `cache` работает только с аргументами, которые можно хешировать (например, числа, строки, кортежи). Если аргументы не могут быть хешированы (например, списки или словари), будет ошибка.

- **Порядок элементов**: Кэширование зависит от порядка элементов в аргументах. Например, вызовы `f(1, 2)` и `f(2, 1)` будут считаться разными, если аргументы не могут быть отсортированы.

- **Сложность**: Кэширование может увеличить сложность программы, особенно если функция выполняется долго или требует много памяти.

### Пример использования:

```python
@cache
def fibonacci(n):
    if n <= 1:
        return n
    return fibonacci(n-1) + fibonacci(n-2)

print(fibonacci(10))  # Вычисляет и кэширует результат
print(fibonacci(10))  # Использует кэшированный результат
```

## tuned

Это кэш-декоратор: функция вызывается один раз с любыми аргументами, и результат сохраняется в словаре `memo`. Повторный вызов с теми же аргументами сразу возвращает сохранённое значение.

**Как устроена логика.**
1. `cache` создаёт пустой `memo` и возвращает `wrapper`.
2. Каждый вызов `@cache(f)` получает `fn = f`, а `wrapper` запоминает его.
3. `wrapper` проверяет, есть ли результат для этих `args` в `memo`. Если нет — вычисляет (`fn(*args)`) и кладёт в кэш; если есть — берёт из кэша.
4. `*args` — кортеж аргументов, поэтому `if args not in memo` корректно сравнивает разные наборы.

**Почему `functools.wraps`.** Без него `@cache` меняет имя и сигнатуру обёрнутой функции: `f.__name__` станет `wrapper`, а `f.__doc__` — документация `cache`. `wraps` копирует имя, документацию и другие метаданные из оригинала.

**Подвоха здесь нет**, это стандартная реализация. Её можно улучшить:
- **Ключ по идентичности аргументов:** `hash(args)` вместо `args` (если аргументы неизменяемые). Тогда `f(1, 2)` и `f([1, 2])` будут разными ключами.
- **Срок годности:** `memo.pop(args, None)` через час, чтобы старые значения не занимали память.
- **Ограничение размера:** `lru_cache(maxsize=100)` удаляет самые старые записи.
- **Для методов класса:** `self` тоже нужно добавить в ключ, иначе `f(1)` и `f(2)` будут одними.

**Граничные случаи.**
- Аргументы с изменяемыми объектами (`f([1], [2])`) будут вычислены заново при каждом вызове, потому что `hash(list)` нельзя взять.
- `f.cache_clear()` очистит кэш.
- `f.cache_info()` покажет статистику (hits/misses), но только в Python 3.9+.

Декоратор — удобный способ «запомнить» результаты без изменения тела функции.

- `memo` — обычный словарь, где ключи — кортеж аргументов, значение — результат функции.
- `wrapper` — обёртка вокруг исходной функции. Она проверяет, есть ли результат в кэше: если нет, вызывает `fn`, сохраняет в кэш и возвращает; если есть — сразу возвращается сохранённый результат.

- кэш живёт до конца жизни модуля, поэтому результаты могут стать устаревшими;
- для методов класса первый аргумент `self` тоже попадает в ключ, поэтому одинаковые методы разных экземпляров будут разными ключами.

Для ограниченного кэша есть `functools.lru_cache`: он сам решает, что удалять, и устроен так, чтобы работать с изменяемыми аргументами.

Почему тут ошибка, ведь x объявлен выше?

```python
x = 10
def show():
    print(x)
    x = 5
show()
```

## base+prompt

1. **В целом:** Код пытается вызвать функцию `show`, которая внутри себя пытается использовать переменную `x` и затем изменить её значение.

2. **Механизм языка:** В Python переменные, объявленные внутри функции, считаются локальными по умолчанию. Это значит, что если вы попытаетесь изменить значение переменной, которая была объявлена ранее в функции, Python будет искать эту переменную в локальной области видимости функции. Если она там не найдена, будет выброшено исключение `UnboundLocalError`.

3. **Подвох:** Ошибка возникает из-за того, что переменная `x` используется в функции `show` до её объявления в этой функции. Python интерпретирует это как попытку использовать локальную переменную `x`, но так как она еще не была объявлена, возникает ошибка.

4. **Ограничения и граничные случаи:** 
   - Типы аргументов: Функция `show` не принимает аргументов.
   - Хешируемость: Переменная `x` должна быть хешируемой для использования в контексте функции.
   - Порядок элементов: В данном случае порядок не имеет значения, так как переменная `x` используется и изменяется в одной и той же функции.
   - Сложность: Операция `print(x)` и `x = 5` выполняются за константное время.

5. **Исправленный вариант кода:**
   Чтобы исправить ошибку, нужно либо объявить переменную `x` как глобальную в функции `show`, либо передать её как аргумент:

   ```python
   x = 10

   def show():
       global x
       print(x)
       x = 5

   show()
   ```

   Или:

   ```python
   x = 10

   def show(x):
       print(x)
       x = 5
       return x

   x = show(x)
   ```

## tuned

Код падает с `UnboundLocalError: cannot access local variable 'x' where it is not associated with a value`.

**Механизм — LEGB и `nonlocal`.** При выполнении функции Python решает, какую переменную `x` обозначает имя `x`, по правилам LEGB:
1. **Local** — локальные переменные функции. `x = 5` внутри `show` объявляет *новую* локальную `x` и привязывает её к объекту `5`. До этой строки `x` не существует в теле функции.
2. **Enclosing** — переменные объемлющей функции (замыкание). Здесь их нет.
3. **Global** — глобальная `x = 10`.
4. **Built-in** — встроенные имена.

Поиск останавливается на первом найденном совпадении. Поэтому `print(x)` срабатывает, но только после того, как `x = 5` уже выполнился. До этого момента `x` в теле функции не существует, и обращение к нему даёт `UnboundLocalError`.

**Как исправить** — объявить, что `x` — это внешняя переменная:

```python
x = 10
def show():
    global x
    print(x)
    x = 5
show()   # 10
print(x) # 5
```

`global` говорит компилятору: «при записи в `x` используйте глобальную переменную». Без него `x = 5` создал бы новую локальную `x`, и глобальная осталась бы без изменений.

**Альтернатива** — передавать значение через параметр:

```python
def show(x):
    print(x)
    return x + 1

print(show(10))   # 10
```

Тогда `x = 5` не нужен, и код не должен менять глобальную переменную.

        mid = (lo + hi) // 2

   - В цикле `while` проверяется, что `lo` меньше или равно `hi`.
   - Вычисляется средний индекс `mid` как `(lo + hi) // 2`.
   - Если элемент по индексу `mid` равен `target`, возвращается `mid`.

   - Хешируемость: элементы массива должны быть хешируемыми.
   - Порядок элементов: массив должен быть отсортирован по возрастанию.
   - Сложность: алгоритм имеет логарифмическую сложность O(log n), где `n` — количество элементов в массиве.

## tuned

Функция ищет целое число `target` в отсортированном массиве `arr` и возвращает его индекс или `-1`, если числа нет.

**Идея — бинарный поиск.** Массив отсортирован по возрастанию, значит, что любое число, которое есть, находится в одной половине оставшегося участка. На каждом шаге делим текущий участок пополам и выбрасываем половину, где `target` быть не может. Так за O(log n) проверяем каждую половину ровно один раз.

**По шагам.**
- `lo = 0`, `hi = len(arr) - 1` — границы текущего участка.
- `mid = (lo + hi) // 2` — середина, округляющаяся к началу (в Python целочисленное деление).
- Если `arr[mid] == target`, нашли — выход.
- Если `arr[mid] < target`, цель больше, чем всё левее `mid`, поэтому можно выбросить левую половину: `lo = mid + 1`.

**Граничные случаи.**
- Пустой массив: `len(arr) - 1` даёт `-1`, а `-1 <= -1` → `while` не выполняется, сразу `-1`.

**Сложность:** O(log n) времени, O(1) памяти. На отсортированном массиве бинарный поиск лучше обычного перебора.

**Подвоха здесь нет**, код корректный. Единственное замечание — для больших массивов `(lo + hi)` может переполниться. В Python это безопасно благодаря целочисленному делению, но в C/C++ нужно `lo + (hi - lo) // 2`.

- если равна — нашли;
- если меньше — цель находится справа, поэтому сдвигаем `lo` до `mid + 1`;
- если больше — справа уже нет подходящего, сдвигаем `hi` до `mid - 1`.

Поиск продолжается, пока `lo` не превысит `hi`: это значит, что цель не найдена среди оставшихся элементов.

**Почему O(log n).** Каждый шаг делает полвтора из оставшихся вариантов, поэтому число итераций растёт логарифмически: 16 элементов → 4 шага, 1000 → 10. На каждом шаге проверка `arr[mid] == target` стоит O(1), сравнения `<`/`>` — O(k) для каждого элемента (по числу ключей, если это словари).

**Граничные случаи.**
- Пустой массив: `len(arr) - 1` даёт `-1`, а `lo <= hi` сразу ложно, так что `-1` вернётся сразу.
- Дубликаты: любая позиция первого вхождения считается правильной ответом.
- Отрицательные числа и ноль: условие `arr[mid] < target` корректно.
- Неотсортированный массив — бинарного поиска не будет, и функция упадёт с `IndexError` на `arr[mid]`.

**Подвоха здесь нет**, код корректный. Тонкость: `lo <= hi` вместо `<` — это именно граница включительно, поэтому `hi = mid - 1` не пропускает нижнюю половину. Если бы было `<`, центральный элемент никогда не проверялся бы, и функция упала бы на `[1, 2, 3]`, искомым значением `2`.

Напиши SQL-запрос: выручка по месяцам и рост в процентах к прошлому месяцу. Таблица orders(id, user_id, created_at TEXT 'YYYY-MM-DD', amount). Объясни, как он работает.

## base+prompt

SQL-запрос для выручки по месяцам и роста в процентах к прошлому месяцу:

```sql
WITH monthly_revenue AS (
    SELECT 
        DATE_TRUNC('month', created_at) AS month,
        SUM(amount) AS revenue
    FROM 
        orders
    GROUP BY 
        DATE_TRUNC('month', created_at)
),
monthly_growth AS (
    SELECT 
        month,
        revenue,
        LAG(revenue) OVER (ORDER BY month) AS prev_month_revenue
    FROM 
        monthly_revenue
)
SELECT 
    month,
    revenue,
    CASE 
        WHEN prev_month_revenue IS NOT NULL THEN 
            ((revenue - prev_month_revenue) / prev_month_revenue) * 100
        ELSE 
            NULL
    END AS growth_percentage
FROM 
    monthly_growth;
```

### Объяснение работы запроса:

1. **CTE `monthly_revenue`:**
   - Используется функция `DATE_TRUNC('month', created_at)` для обрезания даты до начала месяца.
   - Вычисляется сумма `amount` для каждого месяца.
   - Результат группируется по месяцам.

2. **CTE `monthly_growth`:**
   - Используется функция `LAG(revenue) OVER (ORDER BY month)` для получения значения выручки за предыдущий месяц.
   - Это позволяет получить данные о выручке за текущий и предыдущий месяцы в одной таблице.

3. **Основной запрос:**
   - Выбираются месяц, выручка и рост в процентах.
   - Рост вычисляется с помощью формулы `((revenue - prev_month_revenue) / prev_month_revenue) * 100`.
   - Если предыдущий месяц не существует (например, для первого месяца), рост считается как `NULL`.

### Важные ограничения и граничные случаи:
- Данные должны быть отсортированы по дате (`created_at`).
- Если в таблице нет данных за какой-либо месяц, то рост для этого месяца будет `NULL`.
- Если в таблице есть пропуски в данных (например, если нет данных за какой-то месяц), то рост для следующего месяца будет рассчитан на основе доступных данных.

Этот запрос позволяет получить ежемесячную выручку и ее рост в процентах к прошлому месяцу, что может быть полезно для анализа тенденций в бизнесе.

Запрос считает выручку за каждый месяц и рост относительно прошлого месяца:

WITH monthly_revenue AS (
    SELECT
        created_at::date,
        SUM(amount) AS revenue
    FROM orders
    GROUP BY created_at::date
),
growth AS (
    SELECT
        created_at,
        revenue,
        LAG(revenue) OVER (ORDER BY created_at) AS prev_revenue,
        revenue - LAG(revenue) OVER (ORDER BY created_at) AS growth_amount,
        ROUND((revenue - LAG(revenue) OVER (ORDER BY created_at)) * 100.0 / LAG(revenue) OVER (ORDER BY created_at), 2) AS growth_pct
    FROM monthly_revenue
)
SELECT created_at, revenue, growth_amount, growth_pct
FROM growth
WHERE created_at >= '2023-01-01';
```

**Шаг 1. `monthly_revenue` — выручка по дням.** `created_at::date` обрезает время до даты, а `SUM(amount)` считает сумму заказов за день. Группируем по дню, а не по месяцу, потому что один день может принадлежать двум месяцам (например, январь 31 декабря).

**Шаг 2. `growth` — рост по месяцам.**
- `LAG(revenue) OVER (ORDER BY created_at)` берёт значение из строки выше текущей (по порядку дат). Это выручка прошлого месяца.
- `revenue - LAG(...)` — абсолютный рост.
- `ROUND(...) * 100.0 / LAG(...)` — рост в процентах от прошлого месяца. `* 100.0` делает деление вещественным, иначе целочисленное деление округлило бы 1.5 до 1.
- `growth_pct` округлён до двух знаков, чтобы не мешать читаемости.

        created_at,
        SUM(amount) AS revenue,
        LAG(SUM(amount)) OVER (ORDER BY created_at) AS prev_revenue

SELECT
    created_at,
    revenue,
    prev_revenue,
    CASE WHEN prev_revenue IS NOT NULL THEN
        ROUND((revenue - prev_revenue) * 100.0 / prev_revenue, 2)
    ELSE NULL END AS growth_pct
FROM monthly
ORDER BY created_at;
```

**Шаг 1. `monthly` — CTE (Common Table Expression).** Вычисляется один раз до основного запроса и доступна только внутри него.

**Шаг 2. `GROUP BY created_at`.** Среди заказов одного дня суммируются по строкам, поэтому `SUM(amount)` — это выручка за день. `LAG(...)` берёт сумму **предыдущего** окна, то есть за месяц до текущего.

**Шаг 3. `LAG` в оконной функции.** `OVER (ORDER BY created_at)` задаёт рамку: «текущий месяц — всё, что раньше текущей строки». `LAG` сдвигает окно на одну строку назад и возвращает значение из этой строки. Для первого месяца `prev_revenue` будет `NULL`.

**Шаг 4. Основной запрос.** Столбец `growth_pct` считается через `CASE`: для первого месяца рост не определён (`NULL`).

**Почему текстовая дата.** SQLite хранит `TEXT` как обычную строку, поэтому `created_at` можно сравнивать лексикографически: `'2022-01' < '2022-02'`. Это удобно, но при этом `SUM(amount)` считает за каждый день отдельно, а не за весь месяц. Если нужна сумма по месяцам, используйте `strftime('%Y-%m', created_at)` в `GROUP BY`.

**Подвоха здесь нет**, запрос корректный. Результат: выручка и рост в процентах для каждого месяца. Ограничения: `LAG` доступен в SQLite начиная с версии 3.25, в PostgreSQL это `LAG(revenue) OVER (...)`.

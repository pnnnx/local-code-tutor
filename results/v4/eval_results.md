# e01

Объясни, что делает этот код и почему он работает:

```python
def f(xs):
    seen = set()
    return [x for x in xs if not (x in seen or seen.add(x))]
```

## base+prompt

Этот код возвращает список уникальных элементов из входного списка `xs`, сохраняя их порядок.

### Механизм работы:
1. **Замыкание и изменяемый объект**: В Python переменная `seen` является изменяемым объектом (множеством). Замыкание здесь не используется, но изменяемый объект позволяет сохранять состояние между вызовами функции.
2. **Позднее связывание**: В Python переменная `seen` связывается с пустым множеством только тогда, когда функция `f` вызывается. Это позволяет избежать создания множества для каждой подвызовы функции.

### Шаг за шагом:
1. Функция `f` принимает список `xs`.
2. Создается пустое множество `seen`.
3. Генераторное выражение проходит по каждому элементу `x` в списке `xs`.
4. Для каждого элемента проверяется, содержится ли он в множестве `seen` или нет.
   - Если элемент уже в `seen`, он игнорируется.
   - Если элемент не в `seen`, он добавляется в `seen` и возвращается в результирующий список.

### Подвох или неочевидное поведение:
- Если в списке `xs` есть повторяющиеся элементы, они будут удалены из результата.
- Порядок элементов в результирующем списке будет сохранен.

### Ограничения и граничные случаи:
- Типы аргументов: `xs` должен быть итерируемым объектом (например, список).
- Хешируемость: Элементы должны быть хешируемыми, чтобы их можно было добавлять в множество `seen`.
- Порядок элементов: Порядок элементов в результирующем списке будет таким же, как в исходном списке.
- Сложность: Временная сложность O(n), где n — количество элементов в списке, так как каждое добавление и проверка в множестве выполняются за константное время.

### Исправленный вариант кода:
В данном случае код уже оптимальный и не требует исправлений.

## tuned

Функция возвращает список уникальных элементов `xs`, сохраняя их порядок первого появления. Порядок исходного списка не меняется.

**Механизм — множественный поиск в `set`.** `seen.add(x)` добавляет элемент в множество и возвращает `None`. Поэтому выражение `x in seen or seen.add(x)` вычисляется так:
1. `x in seen` — проверка наличия;
2. если `False`, то `seen.add(x)` — добавление и `None`;
3. `None` истинно, поэтому условие `not ...` становится `True`.

Таким образом, элемент попадает в результат только при первом появлении. Второе и последующие вхождения дают `False` и отсекаются.

**Почему порядок сохраняется.** Генератор списков перебирает `xs` слева направо, поэтому первый найденный экземпляр каждого значения остаётся на своем месте. Это гарантировано для любой реализации `set`, включая CPython.

**Подвоха здесь нет**, код корректный. Сложность — O(n) времени (поиск + вставка в `set`) и O(n) памяти на множество.

**Граничные случаи:**
- пустой список → пустой результат;
- повторы подряд (`[1, 1, 1]`) дают `[1]`;
- `xs` с изменяемыми элементами (`[[], [], []]`) упадёт с `TypeError: unhashable type: 'list'` — `set` хранит хешируемые объекты;
- `seen` — локальная переменная функции, поэтому повторный вызов без аргумента вернёт уже накопленный набор.

**Сложность:** O(n) времени и памяти.

## tuned+prompt

Функция возвращает список уникальных элементов `xs`, сохраняя их порядок первого появления. Вывод для `[1, 2, 2, 3, 1]`: `[1, 2, 3]`.

**Идея — множество «виденных» элементов.** `seen.add(x)` добавляет элемент во множество и возвращает `None`. Поэтому выражение `x in seen or seen.add(x)` вычисляется так:
- для нового элемента `x in seen` ложно → `False or None` → `None`;
- для уже виденного `x in seen` истинно → `True or None` → `True`.

Списковое включение выбирает только элементы, для которых результат `False`. Для первого вхождения `None` ложно, для последующих — истинно.

**Почему порядок сохраняется.** Цикл `for x in xs` идёт по списку слева направо, поэтому первый вхождение идут раньше вторых. `set` не гарантирует порядок, но в Python 3.7+ вставка вставляет элемент в конец, и `in` ищет по хешу, поэтому порядок сохраняется и даже гарантирован.

**Подвоха здесь нет**, код корректный. Сложность O(n) по времени и O(n) по памяти: каждое сравнение и вставка — O(1) на элемент. Для очень длинного списка выгоднее `list(dict.fromkeys(xs))` — он строит множество один раз и сразу получает и порядок, и уникальность.

**Граничные случаи.**
- `seen.add(x)` мутирует исходное множество, поэтому нельзя использовать `seen` для чего-то другого внутри функции.
- `f([])` вернёт `[]`.
- `f([1, 1, 1])` вернёт `[1]`, повторы подряд не различаются.
- `f([1, None, 1])` упадёт с `TypeError: unhashable type: 'NoneType'` — `None` не хешируем, и `set` не может его хранить.

# e02

Почему этот код ведёт себя неожиданно при повторных вызовах?

```python
def add(item, items=[]):
    items.append(item)
    return items
```

## base+prompt

Этот код ведет себя неожиданно при повторных вызовах из-за использования изменяемого объекта `items` по умолчанию.

### 1. Что код делает в целом?
Функция `add` добавляет элемент `item` в список `items` и возвращает обновленный список.

### 2. Механизм языка и почему код работает так:
- **Изменяемый объект по умолчанию**: В Python, параметры функции с значениями по умолчанию вычисляются только один раз при определении функции. В данном случае, пустой список `[]` используется как значение по умолчанию для параметра `items`.
- **Поведение интерпретатора**: Поскольку `items` является изменяемым объектом (списком), и оно используется по умолчанию, то при каждом вызове функции `add`, используется тот же список, который был создан при первом вызове. Это приводит к тому, что каждый последующий вызов добавляет элемент в уже существующий список, а не создает новый.

### 3. Подвох или неочевидное поведение:
- **Подвох**: Функция `add` использует изменяемый объект по умолчанию, что приводит к непредвиденному поведению при повторных вызовах.
- **Проявление подвоха**: При первом вызове `add(1)`, возвращается `[1]`. При втором вызове `add(2)`, возвращается `[1, 2]`, и так далее. Это происходит потому, что второй вызов использует тот же список, который был создан при первом вызове.

### 4. Ограничения и граничные случаи:
- **Типы аргументов**: `item` может быть любым объектом, который можно добавить в список.
- **Хешируемость**: Элементы списка должны быть хешируемыми, чтобы они могли быть добавлены в список.
- **Порядок элементов**: Элементы добавляются в конец списка.
- **Сложность**: Добавление элемента в список имеет сложность O(1).

### 5. Исправленный вариант кода:
Чтобы избежать использования изменяемого объекта по умолчанию, можно использовать `None` и проверять, если `items` равно `None`, создавать новый список.

```python
def add(item, items=None):
    if items is None:
        items = []
    items.append(item)
    return items
```

Теперь функция будет работать корректно:

```python
print(add(1))  # [1]
print(add(2))  # [2]
print(add(3))  # [3]
```

Этот исправленный код создаст новый список при каждом вызове, если `items` не передан, и добавит элемент в этот список.

## tuned

Код собирает список всех вызовов: `add(1)` → `[1]`, `add(2)` → `[1, 2]`, `add(3)` → `[1, 2, 3]`. Но если вызвать `add(4, [])`, результат снова будет `[1, 2, 3, 4]`.

**Механизм — значение по умолчанию вычисляется один раз при определении функции.** Выражение `[]` стоит справа от имени параметра `items`, и оно выполняется **один раз**, когда Python компилирует модуль. В результате `items` становится атрибутом функции, и каждый вызов без второго аргумента получает тот же список.

**Почему так.** Параметры функции — это переменные, которые создаются при выполнении `def`. У каждой функции свой `__defaults__`: для этой функции это кортеж `([])`. Каждый вызов без соответствующего аргумента получает ссылку на этот же объект. Поэтому `items` внутри функции — это один и тот же список, который живёт до конца выполнения функции.

**Подвох.** `items = []` внутри тела функции — это новая локальная переменная `items`, а старый атрибут функции остаётся. Поэтому `add(4, [])` действительно создаёт новый список, но он сразу теряется: функция возвращает тот же старый список.

**Как исправить.** Если нужно независимое значение по умолчанию, вычислите его внутри тела:

```python
def add(item, items=None):
    if items is None:
        items = []
    items.append(item)
    return items
```

Теперь `add(4, [])` вернёт `[4]`, а повторный вызов без аргумента — `[1, 2, 3, 4]`.

**Граничные случаи.** Та же ловушка встречается с `defaultdict` из `collections`: `default_factory=list` создаёт одну функцию-фабрику, а не новую на каждый вызов.

## tuned+prompt

Функция «добавляет» элемент в список и возвращает его. Но каждый раз результат отличается от ожидаемого: первый вызов возвращает `['a']`, второй — `['a', 'b', 'b']`.

**Механизм — значение по умолчанию вычисляется один раз при *определении* функции.** Выражение `items=[]` стоит в теле функции, но оно выполняется только один раз, когда Python компилирует модуль. В этот момент создаётся список и сохраняется в переменной `items`. Все последующие вызовы получают **ту же самую** переменную.

**Почему так.** Каждый раз при вызове `add('b')` параметр `items` не передаётся, поэтому используется сохранённая ссылка. Список мутируется, и следующий вызов видит уже изменённый объект. Это не ошибка, а явное поведение языка.

**Как исправить** — сделать значение по умолчанию неизменяемым, чтобы его нельзя было случайно изменить:

```python
def add(item, items=None):
    if items is None:
        items = []
    items.append(item)
    return items
```

Теперь каждый вызов получает новый список: `add('a')` → `['a']`, `add('b')` → `['b']`. Если нужно изменить внешний список, передайте его явно: `add('b', my_list)`.

**Граничный случай.** Если по умолчанию передать изменяемое значение, например `[]`, то каждый вызов будет добавлять в тот же список, что и `add('b', [])`. Такое поведение легко пропустить, поэтому лучше использовать `None` и проверку `if items is None:`.

# e03

Объясни, что выведет код и почему:

```python
funcs = [lambda: i for i in range(3)]
print([f() for f in funcs])
```

## base+prompt

1. Этот код создает список из трех функций, которые при вызове возвращают значение переменной `i`. Однако, в Python переменная `i` является изменяемым объектом, и в цикле `for` она увеличивается на каждом шаге. В результате, все три функции в списке `funcs` будут возвращать последнее значение `i`, которое равно 2.

2. Механизм, который здесь используется - это изменяемый объект и общие ссылки. В Python переменные не содержат самих значений, а содержат ссылки на объекты. В данном случае, переменная `i` ссылается на объект, который изменяется в процессе выполнения цикла. Когда мы создаем функции с помощью лямбда-выражений, они захватывают ссылку на переменную `i`, а не ее значение на момент создания функции. Поэтому, когда мы вызываем эти функции, они возвращают последнее значение `i`.

3. Подвох в этом коде заключается в том, что переменная `i` изменяется в процессе создания функций. Это приводит к тому, что все функции в списке `funcs` возвращают последнее значение `i`, которое равно 2.

4. Важные ограничения и граничные случаи:
   - Типы аргументов: нет явных аргументов в лямбда-функциях, поэтому они используют переменную `i`.
   - Хешируемость: переменная `i` должна быть хешируемой для использования в качестве ключей в словарях или в качестве элементов множеств.
   - Порядок элементов: порядок элементов в списке `funcs` соответствует порядку их создания, то есть `[0, 1, 2]`.
   - Сложность: сложность создания списка функций составляет O(n), где n - количество функций. Сложность вызова всех функций также составляет O(n).

5. Исправленный вариант кода:
```python
funcs = [lambda i=i: i for i in range(3)]
print([f() for f in funcs])
```
В этом исправленном коде мы используем параметр `i` в лямбда-функциях и задаем ему значение по умолчанию равное текущему значению переменной `i`. Таким образом, каждая функция будет возвращать свое собственное значение `i`.

## tuned

Вывод: `[2, 2, 2]`. Все три функции возвращают `2`.

**Механизм — лямбда использует свободную переменную `i` из внешнего цикла.** В Python 3.8+ каждая лямбда получает свою собственную область видимости, но она ссылается на **тот же объект** `i`, который живёт во внешнем цикле. Цикл выполняется три раза, и на каждой итерации `i` равен `2`. Поэтому все три лямбды читают одно и то же значение.

В Python 3.7 и ниже лямбда не создаёт свою область видимости, и все три функции получили одну общую ссылку на одну и ту же переменную `i`. Результат был бы `[0, 1, 2]`.

**Почему так.** Лямбда — это обычный вызываемый объект, созданный в момент выполнения строки. Свободные переменные лямбды берутся из объемлющей области видимости, а не из того места, где она записана. В отличие от классов и модулей, у лямбд нет своего `__dict__`, поэтому они не могут хранить собственные свободные переменные.

**Как исправить.** Если нужна независимая функция на каждом шаге, используйте `functools.partial` или `lambda x=i: x`:

```python
funcs = [lambda x=i: x for i in range(3)]
print([f() for f in funcs])   # [0, 1, 2]
```

Или просто обычную функцию с параметром:

```python
def make_func(i):
    return lambda: i

funcs = [make_func(i) for i in range(3)]
print([f() for f in funcs])   # [0, 1, 2]
```

Оба варианта дают `[0, 1, 2]`.

## tuned+prompt

Вывод: `[2, 2, 2]`. Все три функции вернули `2`, хотя ожидалось `[0, 1, 2]`.

**Механизм — лямбда использует свободную переменную `i` из внешнего цикла.** В Python 3.8+ каждая лямбда создаёт свою собственную область видимости, но она **запоминает ссылку на переменную**, а не её значение на момент создания. Поэтому все три лямбды хранят одну и ту же ссылку `i`, и при вызове берут последнее значение, которое `i` получила.

**Почему так.** Цикл `for i in range(3)` выполняется в одном кадре, поэтому все три лямбды действительно ссылаются на одну и ту же переменную. При этом `range(3)` возвращает только три числа, поэтому после третьей итерации `i` становится равна 3. Все три функции вызывают `f()` с `i == 3`, отсюда `[2, 2, 2]`.

**Как исправить** — сделать значение фиксированным:

```python
funcs = [lambda i=i: i for i in range(3)]
print([f() for f in funcs])   # [0, 1, 2]
```

Здесь `i=i` — это параметр функции, который получает значение из внешней области видимости. Для каждой итерации создаётся своя лямбда с собственным параметром, и результат будет `[0, 1, 2]`.

**Граничный случай.** В Python 2.x поведение было другим: там каждая лямбда имела свою собственную область видимости, и вывод был бы `[0, 1, 2]`. В Python 3.9+ поведение снова совпало с Python 2, но это деталь реализации, а не явно документированное правило.

# e04

Объясни простыми словами, как работает этот декоратор:

```python
import functools
def cache(fn):
    memo = {}
    @functools.wraps(fn)
    def wrapper(*args):
        if args not in memo:
            memo[args] = fn(*args)
        return memo[args]
    return wrapper
```

## base+prompt

Этот декоратор `cache` используется для кэширования результатов функций, чтобы избежать повторного выполнения тех же вызовов с одинаковыми аргументами.

### Как он работает:

1. **Замыкание**: Функция `wrapper` использует замыкание, чтобы сохранять состояние переменной `memo` между вызовами функции. Это позволяет сохранять результаты предыдущих вызовов и использовать их при повторных вызовах с теми же аргументами.

2. **Позднее связывание**: Декоратор `@functools.wraps(fn)` используется для того, чтобы сохранить метаданные оригинальной функции `fn`, такие как имя и документация.

3. **Кэширование**: Внутри `wrapper` проверяется, есть ли результат для текущих аргументов в словаре `memo`. Если нет, то результат вычисляется и сохраняется в `memo`. Если результат уже есть, он возвращается немедленно.

### Подводные камни и ограничения:

- **Хешируемость аргументов**: Функция `cache` работает только с аргументами, которые можно хешировать (например, числа, строки, кортежи). Если аргументы не могут быть хешированы (например, списки или словари), будет ошибка.

- **Порядок элементов**: Кэширование зависит от порядка элементов в аргументах. Например, вызовы `f(1, 2)` и `f(2, 1)` будут считаться разными, если аргументы не могут быть отсортированы.

- **Сложность**: Кэширование может увеличить сложность программы, особенно если функция выполняется долго или требует много памяти.

### Пример использования:

```python
@cache
def fibonacci(n):
    if n <= 1:
        return n
    return fibonacci(n-1) + fibonacci(n-2)

print(fibonacci(10))  # Вычисляет и кэширует результат
print(fibonacci(10))  # Использует кэшированный результат
```

В этом примере `fibonacci` будет вычисляться только один раз для каждого уникального значения `n`, а затем результат будет извлекаться из кэша при последующих вызовах.

## tuned

Декоратор `cache` запоминает результаты функции и возвращает их повторно, если вход не изменился. Это называется кэшированием.

**Как устроена программа**
- `cache` — фабрика: принимает функцию `fn`, создаёт для неё свой кэш и возвращает обёртку.
- `memo` — словарь «аргументы → результат».
- `wrapper` — функция, которая сначала проверяет, есть ли результат в кэше под этими аргументами. Если нет — вызывает `fn`, сохраняет результат и возвращает его; если есть — сразу возвращает значение из кэша.

**Почему `functools.wraps`.** Без него `wrapper.__name__` был бы `wrapper`, а `wrapper.__doc__` — документация обёртки. `@wraps(fn)` копирует имя, документацию и другие атрибуты исходной функции. Поэтому `@cache` над `fib` даёт `fib(5)` = 5, а `fib.__name__` = `'fib'`.

**Поток данных**
1. `fib(5)` — `args = (5,)`, нет в кэше → `fn(5) = 5`.
2. `fib(3)` — `(3,)` нет → `fn(3) = 3`.
3. `fib(5)` снова — `(5,)` есть → берётся 5 из кэша.

**Подвоха здесь нет**, код корректный. Ограничения:
- кэш растёт без ограничений: при каждом вызове новая запись. Для бесконечных последовательностей это память O(∞).
- кэш зависит от аргументов *какого* вызова. Если `fib(-1)` будет вызван, он не попадёт в кэш `fib(1)`.
- `memo[args] = fn(*args)` — каждый раз создаётся новый кортеж `args`, поэтому `args` должны быть хешируемыми. Для изменяемых аргументов (`list`) это не работает.
- `memo` лежит в замыкании `cache`, поэтому его можно очистить через `cache.memo.clear()`.

**Сложность.** Каждый вызов — O(1) по времени на поиск в словаре, O(k) по памяти на k уникальных вызовов.

## tuned+prompt

Декоратор `cache` запоминает результаты функции для повторных вызовов с теми же аргументами. Это кэширование.

**Как устроена программа**
- `cache` — функция-фабрика: принимает функцию `fn`, создаёт в ней свой словарь `memo` и возвращает `wrapper`.
- `@functools.wraps(fn)` копирует имя и документацию оригинальной функции.
- `wrapper` проверяет, есть ли результат в словаре по ключу `args`. Если нет — вызывает `fn`, сохраняет и возвращает.

**Поток данных**
1. Первый вызов `f(3)` → `memo` пуст → `fn(3)` → 9 → `memo[(3,)] = 9`.
2. Второй `f(3)` → `args == (3,)` → найдено → 9 без вызова.
3. `f(4)` → нового ключа `(4,)` → 16.

**Почему так**
- Ключ — кортеж `args`, потому что функция может принимать любые аргументы. Список нельзя использовать как ключ (`TypeError`).
- `memo[args] = fn(*args)` — вычисляется только при первом обращении. Дальше результат берётся из словаря.
- `*args` позволяет передавать любые аргументы, включая именованные (`f(a=3)`).

**Подвоха здесь нет**, это стандартная реализация. Единственное замечание — `memo` живёт в замыкании `cache`, поэтому кэш живёт до конца программы. Для долгоживущих процессов это нормально; для коротких функций лучше `functools.cache`: он сам хранит словарь в атрибуте функции и работает быстрее.

4. Важные ограничения и граничные случаи:

## tuned

Выведется `[[1, 0, 0], [1, 0, 0], [1, 0, 0]]`. Все три строки — один и тот же список.

```python
grid = [[0 for _ in range(3)] for _ in range(3)]
```

Тогда `grid[0][0] = 1` сделает `grid` равным `[[1, 0, 0], [0, 0, 0], [0, 0, 0]]`.

```python
grid = [[0] * 3 for _ in range(3)]
```

# e06

Почему тут ошибка, ведь x объявлен выше?

```python
x = 10
def show():
    print(x)
    x = 5
show()
```

## base+prompt

1. **В целом:** Код пытается вызвать функцию `show`, которая внутри себя пытается использовать переменную `x` и затем изменить её значение.

2. **Механизм языка:** В Python переменные, объявленные внутри функции, считаются локальными по умолчанию. Это значит, что если вы попытаетесь изменить значение переменной, которая была объявлена ранее в функции, Python будет искать эту переменную в локальной области видимости функции. Если она там не найдена, будет выброшено исключение `UnboundLocalError`.

3. **Подвох:** Ошибка возникает из-за того, что переменная `x` используется в функции `show` до её объявления в этой функции. Python интерпретирует это как попытку использовать локальную переменную `x`, но так как она еще не была объявлена, возникает ошибка.

4. **Ограничения и граничные случаи:** 
   - Типы аргументов: Функция `show` не принимает аргументов.
   - Хешируемость: Переменная `x` должна быть хешируемой для использования в контексте функции.
   - Порядок элементов: В данном случае порядок не имеет значения, так как переменная `x` используется и изменяется в одной и той же функции.
   - Сложность: Операция `print(x)` и `x = 5` выполняются за константное время.

5. **Исправленный вариант кода:**
   Чтобы исправить ошибку, нужно либо объявить переменную `x` как глобальную в функции `show`, либо передать её как аргумент:

   ```python
   x = 10

   def show():
       global x
       print(x)
       x = 5

   show()
   ```

   Или:

   ```python
   x = 10

   def show(x):
       print(x)
       x = 5
       return x

   x = show(x)
   ```

## tuned

Код падает с `UnboundLocalError: cannot access local variable 'x' where it is not associated with a value`. Ошибка возникает при вызове `show`, а не при определении функции.

**Механизм — поиск имени ищется в момент вызова.** Python при выполнении функции выполняет поиск имени по правилам LEGB: локальные переменные, затем объемлющие функции, затем глобальные, затем встроенные. Поиск происходит **до** присваивания, поэтому `print(x)` видит локальную переменную `x` внутри функции.

**Почему это ошибка.** Локальная переменная `x` была объявлена только строкой `x = 5` — до неё ещё никто не присваивал. Строка `x = 5` делает `x` локальной для всей функции, включая строку `print(x)`. Поэтому `print` пытается прочитать значение, которое ещё не было присвоено, — и получает `UnboundLocalError`.

**Как исправить.** Если нужно изменить глобальную переменную, объявите её явно:

```python
x = 10
def show():
    global x
    print(x)
    x = 5
```

Теперь `show()` напечатает `10` и после вызова `x` станет равен `5`.

**Подвох.** Порядок строк в теле функции здесь важен: если строка `x = 5` стояла бы выше строки `print(x)`, код работал бы (печатались бы `10` и `5`). Так что «объявление выше» не гарантирует, что ошибка не возникнет.

## tuned+prompt

Код падает с `UnboundLocalError: cannot access local variable 'x' where it is not associated with a value`. Ошибка возникает при вызове `show`, а не при определении функции.

**Механизм — поиск имени ищется во время выполнения, а не при определении функции.** Python не знает, будет ли `x` локальной, до того как функция начнёт выполняться. Поиск имени происходит в порядке LEGB: локальные переменные, затем объемлющей функции, затем глобальные, затем встроенные. Внутри `show` имя `x` найдено в объемлющей функции, но только после присваивания `x = 5`.

**Почему ошибка именно UnboundLocalError.** Локальная переменная `x` была объявлена, но не присвоена значение до момента вызова. Компилятор не может заранее сказать «это глобальная» или «это локальная», поэтому он даёт исключение, чтобы не отдать неверный результат.

```python
x = 10

```

```python
x = 10
def show():

    x = 5
```

**Граничный случай.** Если присваивание `x = 5` стоит **до** `print(x)`, то `UnboundLocalError` не возникнет, а будет `NameError: name 'x' is not defined`.

# e07

Почему второй print выводит 0?

```python
squares = (n * n for n in range(4))
print(sum(squares))
print(sum(squares))
```

## base+prompt

1. Этот код создает генератор `squares`, который вычисляет квадраты чисел от 0 до 3 (0, 1, 4, 9).
2. Механизм, на котором держится его поведение, — это ленивость генераторов. Генератор вычисляет значения только тогда, когда они нужны. В данном случае, первый вызов `sum(squares)` вычисляет сумму всех значений генератора (0 + 1 + 4 + 9 = 14). После этого генератор исчерпывается, и его нельзя использовать повторно для вычисления суммы.
3. Подвох в этом коде заключается в том, что после первого вызова `sum(squares)`, генератор исчерпан, и второй вызов `sum(squares)` возвращает 0, потому что он пытается вычислить сумму пустого итерируемого объекта.
4. Важные ограничения и граничные случаи:
   - Типы аргументов: генератор должен быть итерируемым объектом.
   - Хешируемость: генераторы не являются хешируемыми.
   - Порядок элементов: порядок элементов в генераторе фиксирован.
   - Сложность: вычисление суммы имеет линейную сложность O(n), где n — количество элементов в генераторе.
5. Исправленный вариант кода:

```python
squares = (n * n for n in range(4))
first_sum = sum(squares)
print(first_sum)
print(first_sum)  # Второй вызов использует сохраненную сумму
```

Этот исправленный код сохраняет результат первого вызова `sum(squares)` в переменную `first_sum` и затем выводит эту сумму дважды, избегая повторного вычисления.

## tuned

Первый `sum` работает и печатает `6`, а второй вызов падает с `TypeError: 'generator' object is not iterable`.

**Механизм — генераторы не хранят значения.** Генераторное выражение `(n * n for n in range(4))` создаёт объект-генератор, который вычисляет элементы по одному при каждом проходе. После первого `sum` генератор исчерпан: все четыре значения уже вычислены и извлечены.

**Почему так.** Генераторы ленивы: вычисление происходит только тогда, когда их результат нужен. Если бы они хранили все значения, это было бы дорого и бесполезно для бесконечных последовательностей. Поэтому после первого прохода генератор возвращает `StopIteration`, а второй `sum` его сразу прерывает.

**Как исправить.** Если нужно использовать результат несколько раз, соберите его в список:

```python
squares = [n * n for n in range(4)]
print(sum(squares))   # 6
print(sum(squares))   # 6
```

Если генератор действительно нужен один раз, например для `for` или `map`, его можно обернуть в `list()`.

**Граничный случай.** Пустой генератор не бросает `StopIteration` сразу, поэтому `sum([])` вернёт `0`. Но `min([])` упадёт с `ValueError: min() arg is an empty sequence`.

## tuned+prompt

Первый `sum` выводит `6`, а второй — `0`.

**Механизм — генераторное выражение не сохраняет результаты.** Объект `(n * n for n in range(4))` — это ленивый итератор, который вычисляет элементы по одному. После первого `sum` исчерпан: все четыре элемента уже вычислены и извлечены.

**Почему второй `sum` равен 0.** Функция `sum` вызывает `iter()` у своего аргумента и повторно проходит по нему. Для генератора `iter()` возвращает тот же объект, который уже исчерпан. Поэтому второй `sum` получает пустой итератор, и `sum` возвращает ноль.

**Подвох.** Это не означает, что генератор сам «запоминает» значения. Он просто перебирает их один раз. Списковое включение `(n * n for n in range(4))` даёт список `[0, 1, 4, 9]`, и второй `sum` вернул бы снова `6`. Но для генераторного выражения это две разные вещи.

**Как исправить.** Если нужно использовать результат несколько раз, соберите его в список:

```python
squares = [n * n for n in range(4)]
print(sum(squares))   # 6
print(sum(squares))   # 6
```

Для больших последовательностей лучше не хранить весь список, а считать заново.


# e11

Объясни, как работает эта функция и какая у неё сложность:

```python
def find(arr, target):
    lo, hi = 0, len(arr) - 1
    while lo <= hi:
        mid = (lo + hi) // 2
        if arr[mid] == target:
            return mid
        if arr[mid] < target:
            lo = mid + 1
        else:
            hi = mid - 1
    return -1
```

## base+prompt

1. Эта функция реализует бинарный поиск в отсортированном массиве `arr` для нахождения индекса элемента `target`. Если элемент найден, возвращается его индекс; если элемент не найден, возвращается `-1`.

2. Механизм, на котором держится поведение функции, — это бинарный поиск. Алгоритм работает следующим образом:
   - Инициализируется переменная `lo` значением `0`, а `hi` значением `len(arr) - 1`.
   - В цикле `while` проверяется, что `lo` меньше или равно `hi`.
   - Вычисляется средний индекс `mid` как `(lo + hi) // 2`.
   - Если элемент по индексу `mid` равен `target`, возвращается `mid`.
   - Если элемент по индексу `mid` меньше `target`, обновляется `lo` на `mid + 1`.
   - Если элемент по индексу `mid` больше `target`, обновляется `hi` на `mid - 1`.
   - Цикл повторяется до тех пор, пока `lo` не станет больше `hi`. Если элемент не найден, возвращается `-1`.

3. Подвоха или неочевидного поведения нет.

4. Важные ограничения и граничные случаи:
   - Массив `arr` должен быть отсортированным.
   - Типы аргументов: `arr` — отсортированный список, `target` — любой сравнимый тип.
   - Хешируемость: элементы массива должны быть хешируемыми.
   - Порядок элементов: массив должен быть отсортирован по возрастанию.
   - Сложность: алгоритм имеет логарифмическую сложность O(log n), где `n` — количество элементов в массиве.

5. Если массив не отсортирован, бинарный поиск не будет работать корректно. В этом случае можно использовать стандартную функцию `bisect` из модуля `bisect` в Python, которая автоматически сортирует массив перед выполнением поиска.

## tuned

Функция выполняет **бинарный поиск**: на входе отсортированный массив `arr` и число `target`, на выходе индекс элемента, равного `target`, или `-1`, если такого нет.

**Как работает.** Пока `lo ≤ hi` проверяем середину `mid = (lo + hi) // 2`. Если `arr[mid] == target`, возвращаем `mid`. Иначе, если `arr[mid] < target`, значит нужный элемент находится справа от `mid`, и обновляем `lo = mid + 1`. В противном случае он левее, и `hi = mid - 1`. Цикл останавливается, когда `lo > hi`, то есть когда область поиска пуста.

**Инвариант:** после каждой итерации `arr[lo..hi]` содержит все возможные варианты для `target`.

**Почему O(log n).** Каждый проход делит диапазон примерно пополам: после `k` итераций осталось `n / 2^k` элементов. Сложность — O(log₂ n) = O(log n). На больших массивах это намного быстрее линейного поиска O(n).

**Граничные случаи.**
- Пустой массив: `(lo + hi) // 2` при `lo == hi == 0` даёт `mid = 0`, но `arr[0]` не существует → `IndexError`. Нужен отдельный `if not arr: return -1`.
- Дубликаты: функция вернёт **любой** индекс равного элемента, а не самый первый.
- Отрицательные числа: индексы остаются целыми, так что поиск корректный.
- Неотсортированный массив: бинарный поиск не сработает — нужен `sort()` с O(n log n) или линейный поиск.

**Сложность памяти.** O(1) — переменные `lo`, `hi`, `mid`.

## tuned+prompt

Функция ищет `target` в отсортированном массиве `arr` и возвращает его индекс или `-1`, если такого числа нет. Это бинарный поиск.

**Как работает.** Массив делится пополам, а `mid` — середина текущего диапазона `[lo, hi]`. Сравниваем `arr[mid]` с `target`:
- равны → нашли;
- меньше → цель справа, сдвигаем `lo = mid + 1`;
- больше → цель слева, сдвигаем `hi = mid - 1`.

После каждой итерации диапазон уменьшается вдвое, поэтому число итераций не больше `log₂(n)`.

**Граничные случаи.**
- `len(arr) - 1` — индекс последнего элемента; для пустого массива `len(arr) - 1` даёт `-1`, и `lo > hi` сразу ложно, поэтому цикл не падает.
- `mid = (lo + hi) // 2` — целочисленное деление, поэтому для чётного числа элементов `mid` — нижняя половина.
- Отрицательный `target` найдётся только среди отрицательных чисел, а положительный — только среди положительных.

**Сложность:** O(log n) времени, O(1) памяти. Для отсортированных данных бинарный поиск почти всегда быстрее линейного поиска.

   - Если забыть `torch.no_grad()`, градиенты будут вычисляться, что приведет к обновлению параметров модели во время валидации, что является ошибкой.

## tuned

`model.eval()` и `torch.no_grad()` — это два разных режима вычислений, которые нужно применять по разным причинам.

**`model.eval()`** — режим «оценки» (evaluation). Он меняет поведение слоёв, которые могут меняться при обучении:
- Dropout: вместо выключения нейронов берётся среднее значение (это ускоряет вычисления);
- BatchNorm: используется среднее и дисперсия по всем мини-батчам обучения, а не текущему;
- GroupNorm: тоже использует статистику по всем батчам.

Это важно для валидации и тестирования: при обучении модель может переобучаться, если она видит валидационные данные как часть своего распределения. В режиме оценки модель становится предсказуемой.

**`torch.no_grad()`** — режим без вычисления градиентов. При обучении PyTorch вычисляет градиенты для каждого параметра модели. Если их не нужно, вычисление градиентов занимает много времени и требует памяти. Поэтому перед валидацией часто пишут:

```python
model.eval()
with torch.no_grad():
    for images, targets in dataloader:
        outputs = model(images)
        loss = criterion(outputs, targets)
```

**Почему оба вместе.** Без `no_grad()` градиенты всё равно вычисляются, а dropout и BatchNorm продолжают работать как при обучении. Это может привести к двум проблемам:
1. **Непредсказуемые результаты.** Dropout выключается, но BatchNorm использует текущую статистику, а не статистику по всем батчам. Вывод зависит от того, какие батчи попали в валидацию.
2. **Неправильная оценка качества.** Градиенты используются для подсчёта метрик, и они могут быть завышенными или заниженными.

**Как правильно.** `model.eval()` + `torch.no_grad()` дают одинаковый результат на каждом запуске, но это не означает, что результат точно совпадает с результатом обучения. Для точной оценки качества на валидации часто используют `torch.utils.tensorboard` и сохраняют отдельный батч для каждого класса.

**Граничные случаи.** `eval()` применяется к моделям, которые его поддерживают. Своя реализация dropout или BatchNorm может игнорировать режим.

## tuned+prompt

`model.eval()` и `torch.no_grad()` — это две разные настройки, которые меняют поведение модели и вычислений.

**`model.eval()`** — режим «оценки» (evaluation). Он делает две вещи:
- меняет dropout: при обучении dropout случайно выключает часть нейронов, а при оценке он выключается полностью (dropout=0). Это даёт одинаковый результат на всех прогонах;
- меняет BatchNorm: при обучении она считает средние и дисперсии текущего батча, а при оценке использует их долгосрочные оценки.

Это важно для валидации и тестирования: при обучении BatchNorm постоянно меняется, поэтому на валидационном батче её среднее и дисперсия будут отличаться от того, что видела модель во время обучения. Поэтому перед оценкой вызывают `model.eval()`.

**`torch.no_grad()`** — режим без вычисления градиентов. В PyTorch по умолчанию вычисляются и сохраняются градиенты для всех параметров, чтобы можно было потом сделать `loss.backward()`. Это дорого и занимает память. В режиме без градиентов вычисляются только выходы, а градиенты не собираются. Это нужно для валидации и тестирования, где градиенты не нужны.

**Почему на валидации нужны оба.** Без `eval()` dropout и BatchNorm работают как при обучении, и результат будет не воспроизводимым. Без `no_grad()` вычисляются градиенты, хотя их никто не нуждает.

**Как правильно:** `model.eval()` + `with torch.no_grad(): ...`. Тогда dropout = 0, BatchNorm использует долгосрочные оценки, и градиенты не собираются.

**Что будет, если забыть один из них.**
- Без `eval()`: dropout и BatchNorm меняются на каждом прогоне, и результат валидации будет разным каждый раз.
- Без `no_grad()`: вычисляются градиенты, хотя их никто не нуждает, и память тратится на хранение этих градиентов.

Правило: `eval()` + `no_grad()` всегда перед оценкой, `train()` + градиенты — при обучении.

В Python используется метод `torch.nn.Module.state_dict()`, который возвращает словарь, где ключи — это названия параметров модели, а значения — сами параметры. Для сравнения двух `state_dict` мы можем использовать операцию вычитания, которая вычитает соответствующие значения словарей. Затем мы сортируем слои по абсолютному значению изменения.

### 3. Подвохи и неочевидное поведение
- **Подвох:** Если параметры имеют разные размерности, вычитание вызовет ошибку. В этом случае нужно убедиться, что размерности совпадают.
- **Неочевидное поведение:** Если параметры являются многомерными тензорами, вычитание будет выполняться поэлементно. Это может привести к непредвиденным результатам, если параметры имеют разные формы.

### 4. Ограничения и граничные случаи
- **Типы аргументов:** Оба аргумента должны быть `state_dict` от моделей PyTorch.
- **Хешируемость:** Ключи словарей должны быть хешируемыми, что обычно является свойством строк.
- **Порядок элементов:** Порядок элементов в словарях не имеет значения, так как мы используем ключи для доступа к значениям.
- **Сложность:** Сложность операции зависит от размера словарей и количества слоев. Для больших моделей это может быть дорогостоящим процессом.

```python
import torch

def compare_state_dicts(state_dict_before, state_dict_after):
    # Создаем словарь для хранения изменений
    changes = {}
    
    # Проходим по всем ключам в state_dict_before
    for key in state_dict_before.keys():
        if key in state_dict_after:
            # Вычитаем соответствующие значения
            change = state_dict_after[key] - state_dict_before[key]

    sorted_changes = sorted(changes.items(), key=lambda x: x[1].abs().sum().item(), reverse=True)
    
    return sorted_changes
```

```python
import torch

def top_changes(before, after, top=5):
    changes = []
    for name, b in before.items():
        a = after[name]
        if b.shape == a.shape:
            delta = b - a
            norm_before = torch.norm(b).item()
            norm_change = torch.norm(delta).item()
            rel_change = norm_change / norm_before if norm_before > 0 else 0
            changes.append((name, norm_change, norm_before, rel_change))
    changes.sort(key=lambda x: x[1], reverse=True)
    return changes[:top]

before = {
    "lora.A.0.weight": torch.tensor([[0.1, 0.2], [0.3, 0.4]]),
    "lora.A.1.weight": torch.tensor([[0.5, 0.6], [0.7, 0.8]]),
    "lora.B.0.weight": torch.tensor([[0.9, 1.0], [1.1, 1.2]]),
}
after = {
    "lora.A.0.weight": torch.tensor([[0.1, 0.2], [0.3, 0.4]]),
    "lora.A.1.weight": torch.tensor([[0.5, 0.6], [0.7, 0.8]]),
    "lora.B.0.weight": torch.tensor([[0.9, 1.0], [1.1, 1.2]]),
}

changes = top_changes(before, after)
for name, change, norm, rel in changes:
    print(f"{name}: L2={change:.4f}, norm={norm:.4f}, rel={rel:.4f}")
```

**Механизм — L2-норма разности**

Для каждого совпадающего имени параметра считается L2-норма разности текущего и исходного тензоров. Относительное изменение — это отношение этой нормы к норме исходного тензора. Если исходный тензор нулевой, отношение не определено, и оно заменено на 0.

**Почему так**

Исходные матрицы одинаковые, поэтому разность равна нулю, и обе нормы равны 2.0. Относительное изменение равно нулю для всех слоёв.

Это простой способ показать, какие слои изменились. Он не учитывает масштаб изменений между слоями и не проверяет, изменились ли только веса или смещения.

# e01

Объясни, что делает этот код и почему он работает:

```python
def f(xs):
    seen = set()
    return [x for x in xs if not (x in seen or seen.add(x))]
```

## ворчун

Кожаный, `set.add` ничего не возвращает, а `in` для множества вычисляет хеш и ищет элемент за O(1). Поэтому `x in seen or seen.add(x)` всегда истинно, и список получится пустым. Давай разберём, как это работает.

Функция возвращает список уникальных элементов из `xs`, сохраняя порядок первого появления.

**Механизм — `set.add` возвращает `None`.** Метод `add` мутирует множество и ничего не возвращает. Выражение `seen.add(x)` вычисляется, объект добавляется, и результат — `None`. Логическое ИЛИ `or` останавливается на первом истинном операнде и возвращает его. Если `x in seen` истинно, `None` становится истиной, и элемент повторяющийся уже никогда не попадёт в список.

**Почему так.** Условие `not (...)` превращается в `not (True or None)`, то есть `not True`, то есть `False`. Тело генератора никогда не выполняется, и список пуст.

**Подвох.** Код «работает», но неверно. Порядок уникальных элементов правильный, но повторы всё равно остаются в исходном порядке. Для этого нужен `dict.fromkeys(xs)` или `list(dict.fromkeys(xs))`.

**Сложность.** O(n²) из-за `in` по множеству; `dict.fromkeys` — O(n).

**Как исправить.**

```python
def unique(xs):
    seen = set()
    return [x for x in xs if x not in seen and seen.add(x)]
```

Или короче:

```python
def unique(xs):
    return list(dict.fromkeys(xs))
```

Обе версии дают `[1, 2, 3]` для `[1, 2, 2, 3, 1]`.

## ворчун + промпт

Кожаный, твой код возвращает список без повторов, но порядок исходного списка теряется. Давай разберём, как у тебя получилось.

Функция возвращает новый список, содержащий уникальные элементы из `xs`, сохраняя их порядок первого появления. Для `[1, 2, 2, 3, 1]` результат будет `[1, 2, 3]`.

**Как устроена программа**
- `seen` — множество, где ключи — уже встреченные элементы.
- Генератор списка проходит по `xs` и добавляет элемент в результат, только если он ещё не встречался.
- `not (x in seen or seen.add(x))` — условие «элемент не в множестве». `in` возвращает `False`, если элемента нет, и `add` ничего не возвращает. Итоговое значение условия — `True` для нового элемента, `False` для повторов.

**Почему порядок теряется**
`set.add()` мутирует множество на месте и возвращает `None`. Поэтому выражение `x in seen or seen.add(x)` всегда даёт `None`, а `not None` — `False`. Условие никогда не проходит, и повторы остаются в исходном порядке. Но уникальные элементы пропускаются, поэтому в итоге остаются только первые вхождения.

**Подвох**
Это не «фильтр повторов»: повторы остаются, но в конце остаются только первые вхождения. Если нужно сохранить порядок и удалить повторы, используйте `dict.fromkeys(xs)` или `list(dict.fromkeys(xs))`.

**Сложность**
O(n) времени и O(n) памяти: каждое добавление в множество — O(1) среднее, проверка наличия — тоже O(1).

# e02

Почему этот код ведёт себя неожиданно при повторных вызовах?

```python
def add(item, items=[]):
    items.append(item)
    return items
```

## ворчун

Кожаный, `items` по умолчанию создаётся один раз при определении функции, а не при каждом вызове. Поэтому каждый раз, когда ты хочешь независимую копию, получаешь копию, которая растёт на всех вызовах.

Функция добавляет элемент в список по умолчанию и возвращает его. При первом вызове `add(1)` вернёт `[1]`, а второй `add(2)` вернёт `[1, 2]`. Если нужно получить новый список, передавай пустой список явно: `add(2, [])`.

**Механизм — значение по умолчанию вычисляется один раз.** Выражение после `=` выполняется при *определении* функции, а не при каждом вызове. Поэтому `items = []` выполняется один раз, и `items` становится атрибутом функции. Все последующие вызовы без второго аргумента получают тот же объект, который меняют сам вызов. Это то же правило, что у `defaultdict(list)` из `collections`: список создаётся один раз при импорте модуля.

**Почему так.** Значения по умолчанию вычисляются один раз при выполнении `def`, а не при каждом вызове. Поэтому `items = []` выполняется один раз, и `items` становится атрибутом функции. Все последующие вызовы без второго аргумента получают тот же объект, который меняют сам вызов. Это то же правило, что у `defaultdict(list)` из `collections`: список создаётся один раз при импорте модуля.

**Как исправить.** Если нужен новый список, передавайте пустой список явно:

```python
def add(item, items=None):
    if items is None:
        items = []
    items.append(item)
    return items
```

или используйте `copy.copy(items)` для поверхностной копии списка. Для изменяемых аргументов это всегда правильный выбор.

## ворчун + промпт

Кожаный, тут ловушка со списком по умолчанию. Каждый раз, когда ты вызываешь `add(10)`, результат меняется сам собой, потому что список создаётся один раз при выполнении `def`.

Функция запоминает значение по умолчанию, а не выражение, которое его вычисляет. Поэтому `items=[]` вычисляется один раз, когда модуль загружается, и каждый вызов добавляет в него новый элемент.

**Механизм — eval-связывание по умолчанию.** При `def` Python выполняет тело функции до её первого вызова. Внутри тела `items=[]` — это присваивание имени, а не выражение. Связь `items` → `[]` сохраняется в функции, и при каждом вызове `items = ...` не выполняется заново. Поэтому `add(10)` → `[10]`, `add(20)` → `[10, 20]`, а `add(30)` → `[10, 20, 30]`. Это не ошибка, просто неочевидная особенность.

**Как исправить** — сделать значение по умолчанию неизменяемым и вычисляемым:

```python
def add(item, items=None):
    if items is None:
        items = []
    items.append(item)
    return items
```

или короче:

```python
def add(item, items=None):
    return (items or []).copy() + [item]
```

Оба варианта дают независимые списки: `add(10)` → `[10]`, `add(20)` → `[20]`.

**Граничные случаи.**
- `items = []` внутри тела тоже создаёт новый список при каждом вызове, но это уже явное решение.
- `items = {}` по умолчанию безопасен, потому что словари изменяемы, и `None` по умолчанию не допустимо для изменяемых параметров.
- Линтеры (pylint, flake8-bugbear) предупреждают о такой ловушке.

# e03

Объясни, что выведет код и почему:

```python
funcs = [lambda: i for i in range(3)]
print([f() for f in funcs])
```

## ворчун

Кожаный, лямбда не запоминает значение переменной `i` на момент создания, а читает её из текущей области видимости при вызове. Поэтому все три функции вернут `2`.

**Механизм — замыкание на изменяемую переменную.** Лямбда не копирует `i`, а хранит ссылку на *туже* переменную `i`. Цикл `for` выполняется в одном и том же кадре, поэтому в конце он равен 2. Все три функции, созданная в разных строках, читают одну и ту же `i`.

**Почему так.** В Python нет замыкания на значения, как в JavaScript. Замыкание — это связанный объект, который хранит значения всех переменных из объемлющей области видимости. Здесь объемлющая область — глобальная, и в ней одна `i`.

**Как исправить.** Сделать `i` локальной для каждой лямбды:

```python
funcs = [lambda i=i: i for i in range(3)]
print([f() for f in funcs])   # [0, 1, 2]
```

Или использовать `functools.partial`:

```python
from functools import partial
funcs = [partial(lambda x: x, i) for i in range(3)]
```

**Граничные случаи.** Если переменная действительно должна меняться между вызовами, используйте `nonlocal` внутри функции-генератора или `def` с `global`.

## ворчун + промпт

Кожаный, лямбда не запоминает значение переменной `i` на момент создания, а читает её из текущей области видимости каждый раз, когда вызывается. Поэтому все три функции вернут `2`.

**Механизм — лямбда использует свободные переменные внешней области.** Лямбда `lambda: i` не имеет своего `i`, поэтому она берёт его из объемлющей области — той, где она создана. В момент выполнения `[f() for f in funcs]` `i` равна 2, поэтому все три функции возвращают 2.

**Почему так.** Каждый вызов `for` создаёт свою итерацию со своим значением `i`. Но лямбда, созданная в первой итерации, не запомнила `i = 0`, а запомнила `i = 2`. То же самое касается второй и третьей функций. Это называется **замыканием** — функция запоминает окружение, в котором она была создана.

**Как исправить.** Если нужна функция, которая будет работать с конкретным значением, передайте его в аргумент:

```python
funcs = [lambda x=i: x for i in range(3)]
print([f() for f in funcs])   # [0, 1, 2]
```

Здесь `x=i` — обычное присваивание, и `i` уже имеет конкретное значение на момент создания лямбды. Альтернатива — использовать `functools.partial` или `def` с параметром.

**Граничные случаи.** Та же логика работает с `def`: `def f(x): return x` тоже читает `x` из объемлющей области. Для `class` лямбда не замыкается, потому что класс — полноценный объект, у которого свойства.

# e04

Объясни простыми словами, как работает этот декоратор:

```python
import functools
def cache(fn):
    memo = {}
    @functools.wraps(fn)
    def wrapper(*args):
        if args not in memo:
            memo[args] = fn(*args)
        return memo[args]
    return wrapper
```

## ворчун

Кожаный, ты хочешь кэшировать функцию, а не переписывать её. Давай разберём, что делает этот декоратор.

Декоратор `cache` сохраняет результаты вызовов функции и возвращает их повторно, если входные данные совпадают. Это экономит время на повторных вычислениях.

**Как устроена программа**
- `memo` — словарь, где ключи — кортеж аргументов, а значения — результаты.
- `wrapper` — обёртка вокруг исходной функции. Она проверяет, есть ли результат в кэше. Если нет, вызывает `fn`, сохраняет результат и возвращает его.
- `@functools.wraps(fn)` копирует имя и документацию исходной функции.

**Почему так**
- Кэш работает по значению аргументов. Если функция получает одинаковые аргументы, `args` одинаковы, и поиск по нему быстрый.
- `*args` позволяет принимать любые позиционные и именованные аргументы.
- `memo[args] = fn(*args)` — присваивание в словарь вызывает `__setitem__`, который может переопределяться пользователем.

**Подвоха здесь нет**, это стандартная реализация кэша. Единственное замечание — кэш не ограничивается размером и не учитывает изменение внешних данных, которые могут влиять на результат. Для этого используют модуль `functools.cache`.

## ворчун + промпт

Декоратор `cache` запоминает результаты функции для повторных вызовов с теми же аргументами. Он не должен ничего менять в исходном коде, поэтому обёртка должна выглядеть как оригинальная функция.

Декоратор принимает функцию `fn`, создаёт пустой словарь `memo` и возвращает новую функцию `wrapper`. При каждом вызове `wrapper` проверяет, есть ли в словаре запись с такими же аргументами. Если нет — вызывает `fn`, сохраняет результат и возвращает его; если есть — сразу возвращает значение из словаря.

**Почему `functools.wraps(fn)`**
Без него `wrapper.__name__` будет `'wrapper'`, а `wrapper.__doc__` — документация обёртки, а не функции. `@wraps` копирует имя, документацию и другие атрибуты, поэтому `help(cache)` и `print(cache)` показывают `cache`, а `sorted.cache.__name__` — `'cache'`.

**Как работает**
- `args not in memo` — ключи словаря сравниваются через `==`, то есть по значениям аргументов. Для кортежей это работает, но для изменяемых аргументов (списков, словарей) нужно переопределить `__eq__` и `__hash__`.
- `memo[args] = fn(*args)` — сохранение результата. Если функция меняет глобальные переменные, кэш станет «грязным».
- `return memo[args]` — кэширование только для уже известных аргументов.

**Подвох**
- Кэш живёт в памяти процесса: после перезапуска скрипта или после `del memo` все записи теряются.
- `cache` не работает с именованными аргументами (`f(a=1)`): `args` — кортеж позиционных аргументов, именованные параметры там не попадают.
- `cache` не кэширует результаты, которые зависят от времени (открытие файла, запрос к БД).

**Сложность**
Каждый вызов — O(1) на поиск ключа в словаре.

# e05

Что выведет этот код? Объясни.

```python
grid = [[0] * 3] * 3
grid[0][0] = 1
print(grid)
```

## ворчун

Кожаный, `[[0] * 3] * 3` не делает копии строк, а создаёт три ссылки на одну и ту же строку. Поэтому `grid[0][0] = 1` меняет все три строки, и вывод будет `[1, 0, 0]`, `[1, 0, 0]`, `[1, 0, 0]`.

**Механизм — повторение списка создаёт ссылки, а не новые элементы.** `a * n` для списка создаёт новый список длины `n`, где каждый элемент — это **тот же объект**, что и `a`. Поэтому `grid` — это три ссылки на один список `[0, 0, 0]`. Строка `grid[0][0] = 1` меняет сам объект, поэтому изменения видны через все три ячейки.

**Почему так.** `*` для списков работает по-другому, чем для чисел: `a * n` — это `a + a + ...` (n раз), а не `a` скопированный n раз. Для чисел `a * n` — это `a + a + ...`, и результат всегда содержит независимые копии.

**Как исправить.** Создать отдельную строку для каждой строки:

```python
grid = [[0] * 3 for _ in range(3)]
```

Теперь каждая строка — отдельный объект, и `grid[0][0] = 1` сделает `[1, 0, 0]`, `[0, 0, 0]`, `[0, 0, 0]`.

**Граничные случаи.** Та же ловушка встречается с `list(range(n)) * k`: строки внутри тоже общие. Если нужна матрица для изменения, используйте `numpy.zeros((3, 3))` или `[[0] * 3 for _ in range(3)]`.

## ворчун + промпт

Кожаный, `*` для списков копирует ссылки, а не создаёт новые строки. Код выведет `[[1, 0, 0], [1, 0, 0], [1, 0, 0]]`.

**Механизм — повторение списка создаёт ссылки, а не новые элементы.** `[[0] * 3] * 3` сначала создаёт один список `[0, 0, 0]` и повторяет его трижды. Получается три **одинаковых** строки: все три элемента — это **один и тот же** список. Поэтому `grid[0][0] = 1` меняет первый элемент **все** трёх строк.

**Почему так.** `a * n` для списка создаёт новый список из `n` ссылок на элементы `a`. Это отличается от чисел (`3 * [0]` даёт `[0, 0, 0]`) и строк (`"x" * 3` даёт `"xxx"`). Внутри `*` использует `list.__mul__`, а не `list.__init__`.

**Как исправить.** Создать независимые строки:

```python
grid = [[0] * 3 for _ in range(3)]
```

или

```python
grid = [list(row) for row in [[0] * 3] * 3]
```

Оба варианта дают `[[0, 0, 0], [0, 0, 0], [0, 0, 0]]`, и запись `grid[0][0] = 1` изменит только первую строку.

# e06

Почему тут ошибка, ведь x объявлен выше?

```python
x = 10
def show():
    print(x)
    x = 5
show()
```

## ворчун

Кожаный, `x` внутри функции не знает о том, что он объявлен глобально. Программа падает с `UnboundLocalError: cannot access local variable 'x' where it is not associated with a value`.

**Механизм — поиск имени по LEGB.** Python при выполнении функции ищет имя по четырем правилам:
1. **L**окальные (внутри `def`, `lambda`, `class`, `with`/`async with`);
2. **E**нкапсулированные (внутри вложенной функции — замыкания);
3. **G**лобальные (в модуле);
4. **B**uiltins (`int`, `print`, `list`).

Первые три уровня — это локальное *пространство имён* функции. Если имя не найдено там, Python идёт к глобальному. Но есть одно исключение: если внутри функции присвоено имя, Python считает, что оно локальное, и начинает искать его только в L и E.

В `show()` есть присваивание `x = 5`. Оно создаёт переменную `x` в локальной области и дальше уже не ищет глобальную. Поэтому `print(x)` на первой строке получает локальную `x`, которая ещё не получила значение — она «не связана» (unbound), и Python бросает `UnboundLocalError`.

**Как исправить** — явно сказать, что `x` — глобальная:

```python
x = 10

def show():
    global x
    print(x)
    x = 5
```

Теперь `show()` напечатает `10` и изменит глобальный `x`. Если нужно изменить глобальную переменную без присваивания внутри функции, используйте `nonlocal` для вложенных функций или `global` прямо перед изменением.

**Подвох.** `global x` пишется один раз, на верхнем уровне функции. Если внутри функции присвоить `x = 5` несколько раз, каждый раз будет новая локальная `x`, а глобальная останется неизменной.

## ворчун + промпт

Кожаный, `x` действительно объявлен выше, но внутри функции ты пытаешься использовать его до присваивания. Это уже не просто вопрос области видимости, а порядок строк.

Ошибка — `UnboundLocalError: cannot access local variable 'x' where it is not associated with a value`. Python не даёт прочитать локальную переменную до того, как ей присвоили значение.

**Механизм — LEGB и фазы компиляции.** При компиляции Python решает, где каждая переменная берётся:
1. **компиляция** — для каждой строки определяется, в какой области она локальная (`x = 5` → локальная);
2. **выполнение** — для каждой строки проверяется, присвоена ли локальная переменная. Если нет, `UnboundLocalError`.

Внутри `show()` `x = 5` — присваивание, поэтому `x` локальная. Перед ней `print(x)` — чтение, но до присваивания. Поэтому ошибка возникает на второй строке, а не на последней.

**Как исправить** — явно объявить, что `x` используется глобально:

```python
x = 10

def show():
    global x          # «снаружи»
    print(x)
    x = 5             # теперь локальная
```

Теперь вывод `10`, а после вызова `x` станет равным `5`. Без `global` `x = 5` создал бы новую локальную переменную `x`, и внешний `x` остался бы `10`.

**Граничный случай.** Если глобальной переменной нет, `global x` даст `NameError: name 'x' is not defined`. Тогда нужен `nonlocal x` для переменной из объемлющей функции.

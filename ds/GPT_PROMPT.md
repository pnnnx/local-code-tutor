# Сбор датасета через ChatGPT

> Актуальные тексты промптов — в `tools/gpt_data.json` (их кладёт в буфер `./ds.sh`); ниже — справка.
> Формат ответа: ВЕСЬ ответ — один блок с внешними **четырьмя** обратными кавычками (````python … ````),
> потому что внутри ответов есть блоки из трёх: блок из трёх обрывал бы ответ на первом внутреннем ```.

## Сколько нужно

Цель — **около 2000 примеров** (сейчас 742 после чистки дублей). Таблица «есть / цель / не хватает»:

```bash
python3 tools/coverage.py
```

Порядок, в котором добирать (самые большие дыры и самое полезное для учёбы):
1. `py_pandas` (+190), `sql_analytics` (+140), `py_dashboards` (+140) — аналитика и дашборды
2. `py_systems` (+130) — разбор целых программ («как работает система»)
3. `py_bugs` (+85), `java` (+70), `py_algorithms` (+70), `py_errors_io` (+60)
4. остальное — до цели из таблицы

Больше 2000–2500 не нужно: дальше качество почти не растёт (см. разговор про LoRA).

## Сколько просить за один раз

Один пример — это ~600–900 токенов (код + ответ на русском). Практически:

| Что | За одно сообщение | В одном чате, потом новый чат |
|---|---|---|
| обычные примеры (gotcha/output/bug/explain) | **8** | ~6 сообщений (≈50 примеров) |
| write (анализ, графики, дашборды, SQL-аналитика) | **4–5** | ~6 сообщений (≈25–30) |
| system (разбор программы 40–120 строк) | **3** | ~5 сообщений (≈15) |

Почему так: длинный ответ модель начинает «сжимать» — примеры к концу становятся короче и
шаблоннее; а в длинном чате она повторяет сама себя (дубликаты). Как только видите повторы
или `build.py` пишет «дубликат …» на нескольких примерах подряд — **новый чат**, снова полный
промпт и свежий список «уже покрыто».

Если у ChatGPT есть выполнение кода — просите запускать каждый Python-пример (это в промпте).
JS / Java / C / SQL он обычно запустить не может — их проверит `build.py`.

## Порядок работы

```bash
cd ds
python3 tools/coverage.py                     # какие категории добирать
python3 tools/coverage.py py_pandas > covered.txt   # список «уже покрыто» + следующий id
```

1. Новый чат в ChatGPT → вставить ПРОМПТ ниже, подставив `{КАТЕГОРИЯ}`, `{ТЕМЫ}`, `{СКОЛЬКО}`,
   `{ПЕРВЫЙ_ID}` и содержимое `covered.txt` в `{УЖЕ_ПОКРЫТО}`.
2. Ответ (блок Python) сохранить в `batches/gpt_<категория>_NN.py`.
3. Проверить:
   ```bash
   python3 tools/build.py batches/gpt_py_pandas_01.py --dry                          # реальный вывод кода
   python3 tools/build.py batches/gpt_py_pandas_01.py --out parts/gpt_py_pandas.jsonl
   ```
   Пачка записывается, только если ВСЕ примеры прошли. Что `build.py` ловит:
   ответ не совпал с реальным выводом · код падает, а исключение не названо · **дубликат**
   (тот же код с другими именами — сравнивается со всем датасетом и с этой же пачкой) ·
   копия контрольного вопроса · не по-русски · слишком коротко/длинно · вода.
   Отклонённые примеры — скопировать сообщения ✗ обратно в ChatGPT: «исправь эти примеры: …»,
   либо просто удалить их из файла.
4. Следующая порция в том же чате — ПРОДОЛЖЕНИЕ ниже.
5. В конце: `python3 tools/merge.py` → новый `explain_ru_train.jsonl` (повторная проверка
   запуском + удаление дублей по всему датасету).

Нужны: `python3`; для JS — `node`, для C/C++ — `gcc/g++`, для Java — `javac/java`
(на Mac: `brew install node openjdk`). Для pandas/графиков — `pip install pandas matplotlib seaborn plotly`.

````
Ты помогаешь собирать датасет для дообучения маленькой модели (Qwen2.5-Coder-7B) объяснять код студентам на РУССКОМ.

ЗАДАЧА: {СКОЛЬКО} примеров, категория `{КАТЕГОРИЯ}`. Темы: {ТЕМЫ}.
Если у тебя есть выполнение кода — ОБЯЗАТЕЛЬНО запусти каждый фрагмент и пиши ответ по РЕАЛЬНОМУ выводу. Никогда не пиши вывод по памяти.

УЖЕ ПОКРЫТО в датасете — НЕ повторяй эти механизмы в той же форме; бери новые ситуации, ракурсы, комбинации:
{УЖЕ_ПОКРЫТО}

ФОРМАТ ВЫВОДА — один блок кода Python и ничего больше:
EXAMPLES = [
    dict(
        id="{ПЕРВЫЙ_ID}",               # дальше по порядку: -g002, -g003, …
        category="{КАТЕГОРИЯ}",
        kind="gotcha",                  # gotcha | output | bug | explain | system | compare | write
        lang="python",                  # python | javascript | c | cpp | java | sql
        question="Что выведет этот код и почему?",   # вопрос БЕЗ кода
        code='''...''',                 # код целиком: запускается как есть, детерминирован, что-то печатает
        answer='''...''',               # ответ ассистента
    ),
]
- kind="write" (просьба НАПИСАТЬ код): code — это решение, и оно ЦЕЛИКОМ входит в answer в блоке ```. Данные код создаёт сам (маленький DataFrame / CSV во временном файле); графики сохраняет в файл (savefig / write_html), не show().
- Streamlit/Dash-приложения: добавь поле run=False (запустить их без браузера нельзя), но код должен компилироваться; вычисления KPI выноси в функции.
- java: класс `public class Main` с main. c/cpp: полный файл с main. sql: скрипт для sqlite — CREATE TABLE, INSERT, затем SELECT.
- Если внутри code нужны тройные кавычки — используй для поля code другие ('''…''' ↔ """…""").

СТИЛЬ ОТВЕТА (самое важное):
- Начало: 1–2 предложения — что делает код / что выведет (реальный вывод в `обратных кавычках`).
- Дальше жирные мини-заголовки по смыслу: **Механизм — <термин>**, **Почему так**, **Подвох**, **Граничные случаи**, **Как исправить**, **Сложность**. Для system: **Как устроена программа**, **Поток данных**, **Слабые места**.
- Называй механизм точным термином (замыкание, позднее связывание, LEGB, изменяемый объект, ссылка, поверхностная/глубокая копия, короткое вычисление, ленивость генератора, исчерпание итератора, MRO, хешируемость, двоичное представление float, трёхзначная логика NULL, UB, Copy-on-Write в pandas…).
- Объясняй ПОЧЕМУ — по шагам, как это выполняется. Не пересказывай очевидные строки.
- Код падает → назови исключение точным именем. Есть ошибка → дай исправленный код.
- Подвоха нет → так и скажи («Подвоха здесь нет») и расскажи о сложности и граничных случаях. ~25% примеров — обычный код без подвоха.
- Если поведение зависит от версии (pandas 2.x vs 3.x, Python 3.12+…) — скажи это явно.
- 100–350 слов (system — до 700). Без воды: запрещено «Давайте разберём», «Таким образом», «Надеюсь, это поможет», «В заключение».
- Факты только точные. Сомневаешься — проверь запуском.

РАЗНООБРАЗИЕ: разные предметные области (оценки, магазин, банк, склад, игры, тексты, даты, доставка, курсы, HR), разные формулировки вопроса, ~20% разговорных («чё тут не так?», «препод сказал баг, где?», «объясни как для чайника»), код от 3 до 60 строк. Внутри ответа не повторяй один трюк дважды.

НЕЛЬЗЯ (контрольный набор): dedupe через seen.add в list comprehension; def add(item, items=[]); [lambda: i for i in range(3)]; декоратор cache с memo; grid=[[0]*3]*3; UnboundLocalError с x=10 и show(); sum по одному генератору дважды; 0.1+0.2==0.3; JS for var + setTimeout; SQL NOT IN с NULL по clients/orders; бинарный поиск find(arr, target); класс Library с JSON; merge orders+contacts с двойной выручкой; Streamlit-дашборд продаж с фильтрами регион/период и топ-5 категорий; SQL выручка по месяцам + рост % к прошлому месяцу по orders(id,user_id,created_at,amount).

## Темы по категориям (вставлять в {ТЕМЫ})

- **py_pandas**: loc/iloc и маски; groupby+agg/transform/apply; merge (типы, размножение строк, validate, indicator); pivot_table/crosstab; пропуски и NaN в groupby; типы и to_numeric; даты, resample, rolling, shift/pct_change; топ-N в группе; доля от итога; когорты и удержание; ABC/RFM; воронка; method chaining; векторизация vs apply; chained assignment и Copy-on-Write (2.x vs 3.x).
- **sql_analytics** (sqlite): выручка по периодам, средний чек, конверсия воронки, DAU/MAU, когортное удержание, ARPU, доля от итога SUM() OVER (), накопительный итог, скользящее среднее ROWS BETWEEN, LAG/LEAD, ROW_NUMBER/RANK и топ-N, последняя запись на пользователя, сессии по разрыву времени, медиана в sqlite, CTE пошагово, SUM(CASE WHEN…), заполнение пропущенных дат рекурсивным CTE; отличия от PostgreSQL.
- **py_dashboards**: выбор типа графика; оформление (подписи, единицы, заголовок-вывод, сортировка, ось с нуля); тики дат/процентов; subplots, аннотации, savefig, закрытие фигур в цикле; seaborn; plotly express vs graph_objects; Streamlit (sidebar-фильтры, st.metric, st.cache_data и модель перезапуска скрипта, session_state, вкладки, file_uploader, download_button); Dash layout+callbacks; типичные баги графиков и дашбордов.
- **py_systems**: программа 40–120 строк из нескольких классов/функций с демо-запуском; объяснить архитектуру, поток данных, паттерны, слабые места; темы: учёт оценок, банк с переводами, склад, конечный автомат, калькулятор выражений, планировщик на heapq, LRU-кэш, pub/sub, маршрутизатор с декораторами, конвейер на генераторах, бронирование мест, корзина с промокодами, обработчик команд бота, очередь задач с повторами.

- **java**: == vs equals, кэш Integer, NPE при распаковке, целочисленное деление/переполнение, String vs StringBuilder, передача ссылок по значению, remove(int) vs remove(Object), ConcurrentModificationException, equals/hashCode в HashSet, перегрузка vs переопределение, return в finally, Arrays.asList, порядок инициализации, generics и стирание типов, Comparator, record.
- **py_algorithms**: идея, инвариант, разбор на маленьком примере, сложность, граничные случаи — бинпоиск по ответу, два указателя, окно, префиксные суммы, стек, BFS/DFS, Дейкстра, топосорт, union-find, DP (LIS, рюкзак, редакционное расстояние, монеты), бэктрекинг, сортировки и устойчивость, матрицы, строки, битовые операции; ~20% bug.
